- 首先执行 `git status --short --branch`、`git branch -vv`、`git remote -v`、`git log --oneline --decorate -20`、`git diff --stat`、`git diff --cached --stat`。

## 五、问题分级

- **P0**：数据丢失、账号/凭据泄露、错误提交状态、破坏性恢复、错误安装身份或可导致广泛不可用的问题。
- **P1**：核心同步、作业跳转、提醒、备份恢复、更新链路中的确定性功能缺陷或高概率回归。
- **P2**：边界处理、可维护性、测试覆盖、文档与版本状态不一致、重要体验问题。
- **P3**：低风险优化、非关键重构和未来产品建议。

每个问题必须提供：严重度、文件路径与行号、触发条件、实际影响、证据、修复建议、所需测试和设备验收要求。无法复现或证据不足的内容标为待验证，不得写成确定 Bug。

## 六、执行顺序

1. 先只读盘点，形成当前状态快照和审计报告。
2. 按 P0、P1、P2 排序，先处理有明确证据且影响范围可控的问题。
3. 每个修复先定位调用方和现有模式，必要时先写能复现问题的测试，再做最小实现。
4. 每个任务完成后运行相关测试；一批改动结束后运行全量分析、测试、原生检查和构建。
5. 同步更新 README、CHANGELOG、ROADMAP、验收文档和计划状态，保证互相一致。
6. 最后复核 diff、Git 状态、远端同步与 CI；提交/推送/发布仅在明确授权后执行。
