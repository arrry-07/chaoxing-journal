# 本地存储合成容量基线（T11）

## 结论
当前证据不支持立即迁移SQLite/Drift。已复现主JSON、账号归档与学期快照的容量增长；应先改善容量预告与错误解释，再用隔离测试包做Android实际I/O和启动测量。本阶段没有修改生产实现、UI、持久化格式或删除策略。

## 可复现方法
在local_app运行：

```powershell
flutter test --no-pub --dart-define=RUN_STORAGE_BENCHMARK=true test/storage_capacity_benchmark_test.dart --reporter expanded
```

默认测试运行跳过此测量，显式启用时使用SharedPreferences.setMockInitialValues，全部为合成身份和数据。没有访问真实偏好文件、凭据、网络或MuMu。每档先建库，2轮热身，7轮取中位数；每条含合成课程/标题、160个中文说明字符、可信截止，约四分之一已提交。CPU计时不包括初次建库和断言的完整对象比较。

## 本机测量结果
字节为UTF-8序列化值大小，不含XML转义、键名、文件系统、内存对象或Android平台开销。偏好合计是在A→B→A账号往返后统计，含活动数据与留存账号归档；不是两个满数据账号的容量，也不是磁盘占用。

## 一致性与边界
- 每轮加载及账号往返后逐ID比较全部toJson字段，验证提交状态和记录内容保留，B账号为空；不只检查条数。
- 12份快照均取同一批合成作业、不含个人备注或个人事项。2000条/份虽在单份限制内，总计4546768字节仍超过4MiB总量上限，decode按约束拒绝；这是限制生效，不等同于已经发生数据丢失。
- 主作业库未见类似的总字节硬上限；账号归档数量随账号增长，持久检查点和损坏副本也可能增加体积。当前测量不覆盖任意账号数量、真实长文本、个人备注或最大8MiB备份封装。
- 395项常规Flutter测试通过，1项容量基线按设计默认跳过；显式启用容量测量通过；静态分析无问题。

## 后续实施门槛
1. 优先做保存前容量估算、可读的超限说明和用户主动导出/删除入口；与暂缓的设置UI一并设计，本轮不新增入口、不自动删除。
2. 若准备存储迁移，先在独立合成测试包测Android落盘、冷启动、账号切换与恢复的P50/P95及内存；不对真实应用清数据或恢复实验备份。
3. 仅当这些实际结果暴露明确瓶颈或事务需求时立项数据库迁移，包含旧JSON读取、迁移后逐项校验、中断恢复、失败回滚和备份；不能仅凭2000条桌面mock测量立项。
4. 本轮保持原有硬上限，不为接受大快照而提高限制或减少验证。
