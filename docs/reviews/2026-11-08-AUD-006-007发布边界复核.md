## AUD-007：公开 APK ABI 与更新安装边界

### 已确认问题

对公开 `chaoxing-journal-1.6.2.apk` 的只读检查结果：

- `aapt` 声明 `native-code: 'arm64-v8a' 'armeabi-v7a' 'x86_64'`。
- ZIP 中 `armeabi-v7a` 只有 `libdartjni.so` 和 `libdatastore_shared_counter.so`，没有 `libflutter.so`。
- 因此公开 APK 向 Android 声明了一个实际无法运行 Flutter 的 32 位 ABI。
- 公开 APK 包名为 `com.example.studyassistant.journal`、versionCode 47，签名证书为 `d36a571510e046dd196d7384f849f82b4fcff05ce3affb334765d5c752265d8a`，证书主题为 Android Debug。

### 本轮修复

1. `android/app/build.gradle` 的 JNI 排除规则改为 `lib/armeabi-v7a/**`，防止未来依赖新增其他 32 位辅助库后重新声明 v7。
2. 新增 `tool/check_apk_abis.py`，对构建后的 APK 同时检查：
   - 不存在期望之外的 ABI；
   - 每个期望 ABI 都存在 `libflutter.so`。
3. CI 在 Debug APK 构建后执行 ABI 检查，后续构建若再次带入 v7 或缺失引擎会失败。
4. 新增纯 JVM `UpdateApkPolicy`：设备端更新预检在没有 `libflutter.so`、引擎 ABI 与包内 ABI 不一致、或设备不支持任何引擎 ABI 时 fail-closed。
5. `MainActivity.inspectApk` 已改用该策略；缺失引擎不再被误判为兼容。

## 正式发布身份门槛

当前证据表明两种安装身份不同：

- 公开体验包：`com.example.studyassistant.journal`，现有体验证书，Android Debug 证书主题。
- 当前 Gradle Release：基础 applicationId 为 `com.example.studyassistant`；`android/key.properties` 不存在，缺少配置时 release 任务被主动阻止。

本轮实际执行 `app:assembleRelease`，Gradle 在配置阶段按预期失败：`Release requires android/key.properties and a private signing key`。因此没有生成或伪造签名 Release 产物。

因此本轮不能生成可覆盖公开 1.6.2 用户的正式签名 Release。维护者必须先明确选择：

1. 保留 `.journal` 包名并建立受控正式签名；需要确认现有安装如何跨证书升级及数据迁移。
2. 延续现有体验证书作为发布身份；需要明确是否为长期正式方案，并妥善保管私钥。
3. 采用新正式包名并执行显式备份、重登和迁移；不同包名不能直接覆盖升级。

在身份决定、密钥可用、签名 APK 身份核对和同签名覆盖升级验证全部完成前，不得修改版本为 `1.6.3+48`，不得提交为最终发布候选，不得上传 GitHub Release 或 COS。
