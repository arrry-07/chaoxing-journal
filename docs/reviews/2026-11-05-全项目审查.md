## 具体问题和最小优化

### F01：重新登录换账号后混合本机记录

**证据与场景：** 首页认证失效可进入 `/login?reauth=1`（`assignment_list_screen.dart:47`），路由允许已登录用户进入该页（`main.dart:205`），账号输入可自由更改。`loginChaoxing` 成功后只替换凭据和身份，再启动同步（`assignment_store.dart:186–202`），没有比较账号、切换数据分区或清理旧账号范围状态。仓库使用固定 key（`local_assignment_repository.dart:9`），继续合并旧清单。

**影响：** A 的作业、隐藏状态和取消关注会影响 B；同班同一作业的主键不含学生身份，A 已交、B 未交时，仓库 `:294–298` 的已完成保护会保留 A 的状态，使 B 的待交作业从首页消失。混合结果还会写入提醒和小组件。前提是本机主动换号，不是远程越权，也不意味着 B 获得 A 的服务端权限；客户端会重新建立 Cookie 会话。

**优化：** 成功登录后先判定稳定账号身份，原子切换账号范围的记录、关注、隐藏、提醒与组件，再发布新身份并同步。优先给持久化数据增加 owner 校验；同账号重新认证保留记录，跨账号合并必须被拒绝。

**验收：** 覆盖 A→B 不同课程、同班同作业 A 已交/B 未交、隐藏/关注隔离、同账号重登、切号失败、重启，以及通知/组件最终归属。

### F02：退出登录无提示清理本机数据

**证据：** 个人页直接将按钮绑定 `store.logout`。`assignment_store.dart:326–350` 调用凭据、仓库和提醒清理；仓库 `:86–101` 还删除隐藏状态、关注和损坏备份。文档说明过退出的清理行为，但执行界面没有说明，也没有确认。

**影响：** 用户为了重新认证而退出，可能丢失无法从服务端重建的本机隐藏和设置记录。

**优化：** 最小改动是确认框明确列出清理范围、提供取消；更完整的方案在 F01 的账号隔离基础上分开“退出账号”和“清除本机记录”，避免保留缓存造成串号。

**验收：** 取消退出不改数据；确认后的实际范围与文案一致；失败时不能呈现已经退出的成功状态。

### F03：跨时区持久化会改变截止时刻

**证据：** 正式接口时间以 local DateTime 构造（`chaoxing_local_client.dart:629`），模型直接 `toIso8601String()`（`assignment.dart:121、125、126`），恢复按当前设备时区解析（`:100–109`）。本地非 UTC 时间的 ISO 输出不带偏移，这是 [Dart 的明确行为](https://api.dart.dev/dart-core/DateTime/toIso8601String.html)。

**场景与影响：** 上海设备保存 `2026-11-06T23:59:00.000`，切到 UTC 后重启，该字符串被重新解释为 UTC 的 23:59，真实截止比原来晚八小时；日历、逾期和重排提醒随之偏移。同一缺口还存在于同步时间和组件快照序列化。

**优化：** 新数据统一存 UTC `Z` 或时间戳，展示统一转北京时间。为旧版无偏移数据制定有依据的兼容策略；无法确认原保存时区时应重新同步或标记待确认，不能直接猜测迁移。

**验收：** 用不同时区的两个进程分别写入/恢复同一 JSON，断言 UTC instant 不变。当前 CI 的各时区独立测试没有覆盖这种跨时区持久化。

### F04：同一作业的详情与首页时间不同

**证据与影响：** 详情直接格式化 `deadlineAt`；首页 `assignment_card.dart:45、49` 显式转 `AssignmentQuery.beijing`。系统不在 UTC+8 时，即使不重启也可能看到不同日期和时刻。这与 F03 的存储问题是不同修复点。

**优化与验收：** 详情、组件等消费者统一使用北京时间展示，并标明时区；在 UTC、上海、洛杉矶检查同一跨午夜截止的首页、详情和日历。

### F05：重启掩盖最近同步问题

**证据：** 部分成功也会写 `sync_data_at`（`assignment_store.dart:438–446`）；恢复仅凭该键存在就创建 `SyncPhase.success`（`:149–152`），不恢复 issues 和失败计数。若此前成功、最近失败，也会恢复为成功。`home_sync_presentation.dart:55–62` 随后只显示更新时间。

**影响：** 用户重开软件后看不到之前的“部分课程未更新”、认证失效或验证操作入口，容易把缓存当作完整最新数据。

**优化与验收：** 保存最后尝试结果、最后有数据成功、最后完整成功和必要问题分类；运行中断恢复为未完成。部分成功、全失败、认证失效、需要验证分别重建 Store，检查状态与处理入口保留。

### F06：课程缓存损坏让有效作业无法离线恢复

**证据：** `loadCourses` 对 `course_refs` 直接 JSON 解码、列表转换和逐项强转，无隔离恢复；`restoreSession` 在 `_reloadJournal` 之前加载它（`assignment_store.dart:154–157`）。任何一条课程损坏都会跳过作业清单加载。

**优化与验收：** 课程引用独立备份、逐项恢复并收集警告，不得阻断有效 journal；用损坏 JSON、错误顶层类型及单条损坏课程配合有效 journal 验证作业仍可读、警告明确。凭据恢复也应与其他恢复阶段分离，但是否允许离线访问须保持账号归属校验。

### F07：协议有强调样式，没有阅读动作

**证据与影响：** 两个协议名称只是静态 TextSpan，没有 recognizer 或路由；`_accepted` 初值为 true。当前加粗和莓红色已生效，但用户无法查看所称已阅读的内容。

**优化：** 先提供真实、可阅读的服务说明和隐私内容，再连接两个入口；建议由用户主动确认同意。可以复用现有隐私指南中的事实，但不能把开发文档或开源许可证直接当作服务协议。此处是交互建议，不作法规合规结论。

**验收：** 两个名称触摸及 TalkBack 均可打开对应内容；返回保留输入；不同意时不能登录。

### F08：协议勾选难以触摸和读屏

**证据与影响：** InkWell 仅包裹 18dp Icon，没有明确 label/checked；附近文字不扩大勾选区域。用户难点中，读屏也无法可靠知道作用及当前状态。

**优化与验收：** 用标准 Checkbox 或等价完整语义，保持 Android 至少 48dp 的操作区域；阅读协议与切换同意分别可访问。检查 label、checked、tap 动作及 TalkBack 宣读。

### F09：提醒保存失败后停在保存中

**证据与影响：** `_save` 先设置 `_saving=true`，直接 await 持久化，没有 try/finally；`saveReminderRule` 的首次存储 await 可抛出异常（`assignment_store.dart:280–283`）。错误后按钮持续禁用，原页无法重试。

**优化与验收：** catch 提供可理解错误，finally 恢复忙碌状态，保留未保存选择。注入首次写入失败、第二次成功，检查错误、选择和重试状态。

### F10：隐藏失败也离开详情

**证据与影响：** `updateCompletion` 经 `_execute` 捕获写入错误并设置 store.error（`assignment_store.dart:529–537`），Future 仍完成。详情 await 后不检查结果，始终返回首页；用户没有就近的失败说明。

**优化与验收：** 命令返回明确成功结果；成功才导航，失败留在详情并显示重试。注入仓储写入失败，确认记录仍可见且页面不把失败表现为成功。

### F11：同步选项缺少选中语义

**证据与影响：** `_IntervalOptionCard` 仅通过背景和勾号表现选择，没有 selected/checked 和互斥组语义。TalkBack 不能可靠确认哪个时间已经生效。

**优化与验收：** 保留视觉，补标准选择语义或采用标准控件；确保一次只有一个选中项，切换后可读出选项和状态，禁用状态一致。

### F12：帮助与更新机制矛盾

**证据与影响：** 帮助问答和版本说明仍称在线更新未启用，实际 `app_update_service.dart:55` 已默认走 GitHub Release。用户可能因此放弃可用的更新入口。

**优化与验收：** 按当前“检查→下载→校验→系统确认安装”改写，保留网络不可达和兼容签名限制；打开两处帮助详情，确认不再出现过期说明。

### F13：登录丢失通知指向的作业

**证据：** URI 已能规范到内部详情，但认证拦截直接返回 `/login`，未保留目标（`main.dart:193–208`）；登录完成又固定去 `/assignments`（`login_screen.dart:167`）。

**优化与验收：** 暂存经过验证的内部目标，登录成功后恢复并清除，目标不存在给出解释和清单入口。用真实 App Router 覆盖未登录深链→登录→指定详情、无效目标、普通登录。已登录冷启动通知有 `_pendingPayload` 缓冲，不应混报为这条链路整体失效。

### F14：个人子页面错误高亮作业页签

`/help`、`/records`、`/courses` 在 AppShell 内，但 `_indexFor` 未将它们映射为“我的”，默认返回 0。将这些个人管理子页归入索引 3，并逐一断言底栏选中状态；无需改整个导航结构。

### F15：升级探针的 PASS 范围不足

探针对账号及作业保留主要检查账号键是否存在、记录数量、提醒字符串是否包含 `60`，没有核对密码或每条作业的状态和截止；它另有旧平台凭据、记录和旧存储键的清理断言。即使数量相同但字段损坏，也可能 PASS。应对固定合成样例逐字段断言，并用密码、状态、截止单字段破坏验证探针会失败；不能把当前 PASS 扩大解释为所有内容完整保留。

## 作业网页与学习通 App 跳转方案

### 现在已经具备什么

1. `Assignment.submitUrl` 已持久化作业链接（`models/assignment.dart:83、105、124`）。正式 V3 读取服务端 `taskUrl` 并检查 HTTPS、超星域和关联身份（`chaoxing_local_client.dart:575–599、637`）；旧签名列表从条目 data 取得独立详情 URL（`chaoxing_assignment_parser.dart:365–397`）。
2. 参考实现 `client.py:839` 明确详情链接来自作业条目，带独立签名；不能拿列表 enc 或几个 ID 随意拼一个替代链接。
3. `ExternalLinkService.openUrl` 和 Android `MainActivity.kt:107–111` 已能将 URL 交给 `ACTION_VIEW`。Android 官方确认这是打开网页的标准方式；实际可能进入浏览器或支持该链接的 App。[网页 Intent](https://developer.android.com/guide/components/intents-common#Browser)、[可用性和失败处理](https://developer.android.com/training/package-visibility/use-cases)
4. 当前作业详情页只展示本地信息及隐藏按钮，未消费 submitUrl；所以主要缺口是入口、有效性和失败反馈，并非从零重做同步。

现有 `studyassistant:///assignments/...` 是**进入本助手**的链接，服务于通知和组件；它不是学习通作业的跳转协议。也不能通过在本助手 Manifest 注册超星域来替学习通建立 App Links；接收 App 与域名关联由对方控制。[Android 深链机制](https://developer.android.com/training/app-links/create-deeplinks)

### 推荐先落地网页入口

首页点作业仍进入本地详情，保留本地截止/状态和离线信息；详情中增加主要动作“打开作业网页”，将“在本机隐藏”降为次要动作。用户不用离开当前信息层级就能理解跳转目的。

- 点击前检查链接非空、HTTPS、允许的超星 host、预期作业路径与可获得的课程/班级/作业身份；拒绝任意 scheme、userinfo 或异常 URL。链接验证应放在实际打开入口，不能只相信历史缓存已被解析器检查过。
- 复用服务端原始详情 URL，不重构签名参数；若已过期或不可用，允许刷新该课程以取得新链接，保留打开官方课程/网页入口的回退。
- 使用一次性打开中状态避免连点；处理 false、PlatformException、无处理器等启动失败。启动后的网络、HTTP、登录和权限结果由目标页面呈现，助手无法仅凭 ACTION_VIEW 自动识别；始终保留用户主动返回后的刷新、重试和复制入口。若要在助手内识别页面错误，应另行设计受限的页面探测或内置浏览流程，并验证登录和隐私边界。外部 Intent 成功只说明系统接收了跳转，不能提示“已进入作业”或“已提交”。
- 文案说明“将在学习通网页中打开，可能需要另行登录”。本助手内存 Cookie、外部浏览器与学习通 App 的登录态没有自动共享；不能承诺免登录。不要把账号密码或 Cookie 拼入 URL；签名 URL 也不应进入日志、反馈模板或分析事件。复制完整链接应由用户主动选择并提示只在本人设备使用。
- 回到助手后保留原详情/滚动位置；可触发一次有明确状态的同步核对，不能因为发生了跳转就标记完成或自动隐藏。

### App 直达有条件可行

Android 支持自定义 scheme、HTTPS 深链及验证后的 App Links，但**必须是学习通自身实际接收并能够路由到作业的格式**。本轮在公开可检索的超星官方资料中未找到足以确认“第三方直达指定作业”的协议说明；没有据此判定它不支持，也没有采用猜测的 scheme。

后续先收集官方分享/打开入口提供的有效链接，或在隔离测试设备中只读核对当前学习通版本的公开 intent filters，再用自己的样例课程验证是否落到目标作业，而不只是拉起 App 首页。确认接收包名、公开入口、所需参数、账号匹配和版本差异后，才增加“在学习通 App 中打开”。不要调用未导出的内部 Activity，也不要把任意字符串交给 `Intent.parseUri`。

建议回退链为：**已验证的学习通 App 入口 → 原始 HTTPS 网页 → 启动失败说明及刷新/复制选项**。要保证网页回退，应显式选择浏览器或使用支持该策略的 Custom Tabs；普通 ACTION_VIEW 打开 HTTPS 仍可能被学习通 App 接管。若 App 能被启动但无法确认目标被打开，保留用户可见的浏览器入口，不把“启动成功”视作“直达成功”。Android 11+ 直接启动并处理失败通常不需要广泛查询全部已安装应用；仅在确实需要预检测时增加最小 `<queries>`。[官方包可见性说明](https://developer.android.com/training/package-visibility/use-cases)

| 验收场景 | 期望结果 |
| --- | --- |
| 有/无学习通 App，旧/新支持版本 | 可直达时进入目标，否则网页回退，助手不闪退 |
| App/浏览器未登录、登录了另一账号 | 显示真实登录/权限页面，不混用本助手凭据，不声称已访问成功 |
| 原链接缺失、过期、无权限、作业已关闭 | 缺链接在助手提示；其余由目标页面呈现真实结果，助手保留刷新或官方入口，不自动标记完成 |
| 恶意 scheme、异常 host、伪造课程/作业身份 | 打开前拒绝，并保持可重试的本地详情 |
| 连点、系统返回、进程恢复 | 不重复启动多页，回到原作业，状态仍需同步核对 |
| 通知→登录→详情→打开外部作业 | 修复 F13 后保留同一作业目标，不能跳回不相关首页 |
