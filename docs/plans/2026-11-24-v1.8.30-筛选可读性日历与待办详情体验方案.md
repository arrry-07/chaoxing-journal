## 5. 设计决策（执行时不再重新取舍）

- **D1 类型筛选**：类型变成「全部 / 作业 / 考试 / 待办」。作业 = 学习通作业加任务；考试 = 学习通考试和考试通知，加上自己添加的考试；待办 = 自己添加的待办。新增 `AssignmentTypeFilter` 值并保持按 `name` 持久化，旧 JSON 照常读取；旧版本读到不认识的值要回落到「全部」，执行时用测试确认。
- **D2 课程列表**：候选 = 当前学期目录里的全部课程，加上有课业的课程（往期、全部学期仍可通过已有切换查看）。排序：有课业的课在前，按当前类型和期限条件下的条目数从多到少；没课业的课在后，按名称排。右侧写数量，没有就写「暂无」，文字颜色正常不变淡。手动条目按课程名和目录同名匹配计数。保留搜索，单选。
- **D3 空课程状态**：选中没有课业的课程时，列表显示「这门课暂无作业和考试」，下面放「为这门课添加待办」按钮，课程名预先填好。替换现在 `assignment_list_screen.dart:1311` 那句「已保留课程筛选…」。
- **D4 筛选入口**：去掉图标，改成一行「课程　全部课程 ▾」，值紧挨着标签。选了课程就显示课程名，旁边放 × 一键清除。
- **D5 红色规则**：红色只用于逾期（「已逾期 N 天」标签和逾期计数）和需要马上处理的错误（同步失败、删除确认）。日期组标题、置顶临近、「今天」时间栏改用墨色或主色；「已截止」改成清晰的灰色；考试标签改成橙色。
- **D6 可读性**：先在 MuMu 浅色和深色主题下各截首页、详情、日历、我的四页并取像素；正文小字的实际对比度不到 4.5:1 的，按测量结果调整。优先顺序：去掉文字颜色上的透明度叠加 → 小字从 12–13 号提到 13.5–14 号 → 必要时再把 `muted` 调深（浅色和深色主题都要调）。
- **D7 字体与中文兜底**：接入 `flutter_localizations`，固定 `zh_CN`，让 Material 组件（关于、许可证、日期和时间选择器）显示中文。加一个组件测试，遍历关键页面所有文字确认用的都是文楷。检查更新页按截图上的实际根因修复。
- **D8 详情页按钮**：两个按钮同高（46）、同宽并排，主按钮实心、次按钮描边（`JournalSecondaryButton`）；窄屏或大字号时改成上下排列。
- **D9 日历**：去掉繁忙底色和「今天」圆环。今天用主色加粗数字表示，选中日期用浅色圆底表示。每个事件一个点，一格最多 3 个，超出加一个小「+」。颜色：作业蓝（`accent`）、考试橙、待办绿，新增两个色板值并在浅色和深色主题下都满足 3:1。逾期不改点的颜色，逾期信息由议程和首页标红表达。日历下方加图例「● 作业 ● 考试 ● 待办」，同步改写圆点说明文案。繁忙信息保留在读屏语义里。
- **D10 待办文案与类型**：编辑器默认就是待办，类型改成轻量分段「待办 / 考试」，放在标题下面，不用先选；从考试入口进来时预选考试。全站「手动考试 / 手动待办 / 个人待办」统一改成「考试 / 待办」，再加一个中性的「自己添加」小标签区分来源。通知标题「个人考试提醒 / 个人待办提醒」改成「考试提醒 / 待办提醒」。
- **D11 待办详情页**：新建 `ManualEntryDetailScreen`（独立文件）。`/assignments/manual/:id` 改为进入详情，编辑走 `/assignments/manual/:id/edit`。个人安排列表、日历议程行、通知 `p:` 负载都改为进入对应条目的详情。详情页显示类型和「自己添加」、时间、课程、地点、提醒状态、预计时长，以及完整备注（可选中、可复制）；操作有完成 / 取消完成、编辑（右上角）、删除（需要确认）。已完成的条目点进去也是详情。
- **D12 备注露出**：首页待办卡片显示备注前 2 行，日历议程行显示 1 行，超出用省略号。桌面小组件不变。
- **D13 遗留 P2**：「提醒或小组件需要处理」改成只在真正有提醒或小组件失败时出现；夜间静音的个人日程改成在该条目上提示。「关于」英文由 D7 解决。
- **D14 通知声音**：先做 M1 真机诊断，按结果选分支修复，不靠猜。分支：(a) 渠道声音为空或被静音 → 新建带显式声音的 `personal_schedule_v2` 并迁移，删除旧渠道（会丢掉用户对旧渠道的自定义设置，要在更新说明里写明）；(b) 提醒落在夜间静音时段 → 改进设置页和条目上的说明；(c) 聚合通知更新只提醒一次 → 保证新事件第一次投递有声；(d) 手机本身是勿扰或静音 → App 内检测并提示。另外在提醒设置页加「测试待办提醒」（发到个人渠道）和「打开系统通知设置」入口（已有入口就复用）。

## 10. Gate 审查要点

- 红色是否只剩逾期和错误；浅色和深色主题的对比度数值是否附了证据。
- 课程列表数量和顺序是否和首页实际显示一致；空课程添加待办时是否预填课程。
- 待办详情、编辑、深链的路由是否完整，返回栈和「未保存离开」确认是否正常。
- D14 选的分支是否有真机证据支持；新渠道迁移是否披露了用户设置会丢失。
- `flutter_localizations` 引入后依赖锁文件是否只有 SDK 范围内的变化。
