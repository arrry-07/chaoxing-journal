## 1. 首页排序与持久化

### 现有入口

- `lib/src/models/home_filters.dart`：`HomeFilters` 当前包含 query、courseKey、deadline，提供 encode/decode。
- `lib/src/local/local_assignment_repository.dart`：`loadHomeFilters` / `saveHomeFilters`，键为 `home_filters_v1`，沿用现有账号存储。
- `lib/src/services/assignment_store.dart`：`homeFilters` / `saveHomeFilters`，已有 accountEpoch 校验及保存失败处理。
- `lib/src/services/assignment_query.dart`：`filterHome` 过滤；`home` 分组并排序。
- `lib/src/features/assignment_list_screen.dart`：`_openFilters`、`_HomeFilterSelection`、`_saveFilters`、默认 timeline 渲染及空结果“清除搜索与期限条件”。

### 修改规格

1. 在 home_filters 模型中增加 `HomeSortOrder { grouped, deadlineAsc, deadlineDesc, courseName, title }`，以及默认 grouped 的 `sortOrder`。持久化使用枚举 name；缺少或无法识别排序字段只回退该字段，不能丢弃合法的旧搜索和课程筛选。保留 `home_filters_v1`，不做破坏性迁移。
2. 在查询层增加纯函数 `sortHome(List<Assignment> records, HomeSortOrder order)`，返回副本，不原地修改 Store 列表。若导入造成循环依赖，将查询所需枚举移入单独模型并保持原使用处兼容。
3. 标签固定为“默认分组”“截止时间：近到远”“截止时间：远到近”“课程名称”“作业名称”。截止时间排序把可信且读取成功的非空日期放前面，待确认放其次，明确无截止时间放最后；倒序只反转可信日期的比较，不将未知日期提到前面。
4. 名称排序采用 `trim().toLowerCase().compareTo`；这是字符顺序，不宣传为拼音顺序。所有并列项依次按课程名称、作业名称、courseKey、id 排序，保证同名多班稳定且不合并。课程排序以课程名称为主，标题排序以标题为主。
5. 筛选面板标题改为“搜索、筛选与排序”，增加单选排序控件；选择仅在点击“应用”且保存成功后生效，取消不写入。保存失败保持旧偏好并提示。
6. 面板“重置”改为“清空筛选”，只清 query/courseKey/deadline。空结果页清除按钮同样携带原 sortOrder，禁止继续直接保存 `const HomeFilters()`。搜索全部 HomeFilters 构造及清除路径，防止隐式丢失排序。
7. grouped 继续调用现有 `AssignmentQuery.home`，不改变现有各组含义。其他排序绕过分组 timeline 和日期标题，用同一个 AssignmentCard 按排序结果渲染单列表；保留卡片完整截止日期，避免只显示 HH:mm 导致跨日歧义。
8. 页面显示当前非默认排序名称；是否“已筛选”仍只由过滤条件决定，不用排序制造错误的空结果提示。

### 验收

扩展 `test/home_filter_persistence_test.dart`、`assignment_query_test.dart`，按需扩展 `home_redesign_test.dart` 或新增排序组件测试：五种模式、同名多班、相同截止时间、失败但缓存有日期、未知年份、无截止、旧 JSON、未知枚举、保存失败、清空筛选、重启恢复、同账号重新登录、换账号及面板打开期间账号变化。名称排序下不得残留日期分组标题。

## 2. 首次登录截止信息渐进显示与延迟排查

### 当前链路及风险

`AssignmentStore.login` 成功后会异步启动同步；`_syncAssignmentsBody` 调用客户端 `fetchAssignments`。客户端按课程逐个调用 `_fetchCourseWork`，其内部 `_hydrateWorkDeadlines` 再逐条 await 详情。Store 等 fetch 完成后才执行提醒 mutation 标记、`repository.mergeAndSave`、报告写入及 `_reloadJournal`。

`AssignmentCard` 只有 `deadlineAt != null && deadlineTrusted && !deadlineReadFailed` 才显示左侧 HH:mm，其余显示“—”。因此不能简单移除可信性条件。

现有并行任务引入后台同步租约、原生会话代次、提醒快照版本、白天检查窗口和服务端退避。不要为了刷新界面逐条调用完整 mergeAndSave 或触发通知重建。

### 先建立可复现证据

1. 阅读 `test/deadline_hydration_test.dart`、`deadline_evidence_test.dart`、`v3_deadline_detail_test.dart`、`assignment_store_login_test.dart` 和客户端请求统计实现。
2. 使用合成响应建立案例：课程列表及作业列表立即返回，第一份详情可控完成，第二份详情由 Completer 延迟。记录首次列表、首次可信日期、全轮结束的相对耗时。
3. 区分三种情况：请求仍执行但首页未更新；本轮详情失败且已结束；后续手动同步因会话/入口改变才成功。截图顶部 partial 不能直接解释成“仍在加载”。
4. 对真实问题只能记录脱敏的阶段、数量、耗时、HTTP 状态和失败类别；禁止记录 Cookie、带签名 URL、账号响应。不能取得真实设备证据时保留该限制，继续完成合成场景修复。

### 实现方式

1. 新增内存进度模型，例如 `AssignmentSyncProgress`，最少包含 stage（courses/list/details）、当前已取得的作业快照、pendingDetailIds、resolvedCount、attemptedCount。回调是可选参数，现有后台调用不传时行为不变。模型不入库、不改变 Assignment 截止字段含义。
2. 在列表解析成功、详情开始、每条详情完成时发布不可变快照。只将确实排队或正在执行的 ID 标为 pending；失败、取消、验证码或登录失效后不能一直显示“正在确认”。覆盖客户端现有不同作业列表分支，不只修改一个解析入口。
3. Store 仅为前台提供 `homeDisplayAssignments` 与进度；首页读取它，其他消费者继续读取已提交的 `visibleAssignments`。预览按 id 合并旧记录，复用现有 `mergeAssignments` 的缓存保护语义，并应用隐藏、关注课程和正式来源过滤。禁止新预览使隐藏作业重新出现。
4. 使用 `_generation`、accountEpoch、disposed 和客户端 session generation 拦截迟到事件。认证重试前清理该轮预览；最终落盘及 reload 完成后清理预览；失败时恢复持久化数据并显示失败原因。不要在请求刚结束但落盘未完成时让列表闪回旧数据。
5. 进度刷新最多每 100ms 合并一次；首批结果和最终状态立即通知。定时器必须在结束、退出和 dispose 时取消。后台检查不创建 UI 定时器。
6. 预览中尚未持久化的新记录只展示信息，查看详情/去完成按钮待落盘后启用，避免路由 findAssignment 找不到对象；已有记录仍走现有入口。界面说明“正在保存”与“正在确认”不能混用。
7. 卡片新增可选加载状态参数，默认不影响其他使用处。pending 时左侧显示小型进度图形及可访问描述，正文“正在确认截止时间”；无 pending 的未知日期显示“待确认”，保留原始月日和年份待确认说明；明确无截止显示“无期限”。已确认数据立即显示具体时间。
8. 顶部运行中显示真实阶段和“已处理 X 项详情”，不要在尚未获取所有列表时虚构总数。结束后维持 success/partial/failed 的准确语义。
9. 首轮保持现有请求串行、超时、退避和验证码保护，不盲目增加并发。优先修复经证据证明的重复请求、错误入口或通知延迟；不通过减少安全检查或猜年份缩短耗时。需要改请求策略时先补压力、认证和中止测试。
10. 本轮重试入口复用现有 `syncAssignments()` 的完整同步及 in-flight 去重，不假称“只重试失败项”。可靠详情专项重试需要新的独立事务和签名刷新策略，明确留到后续，避免本轮破坏提醒一致性。

### 验收

- 控制第二份详情不返回时，第一份可信时间已显示；不必等待整轮或手动刷新。以状态与事件顺序断言，不用脆弱的真实网络秒数断言。
- 验证无截止、未开放、缺年份、超时、验证码、登录失效、部分课程失败、保存失败、后台中止、账号切换和 dispose。

- 原 `deadline_consumers_test.dart`、`deadline_ui_test.dart`、`home_refresh_feedback_test.dart` 及后台提醒测试继续通过。
