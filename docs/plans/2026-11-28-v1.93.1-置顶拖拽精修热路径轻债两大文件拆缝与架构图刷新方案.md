## 2. 关键架构决策与铁律不变量

### 2.1 首页置顶拖动排序根因与交互契约（M1）

经实查 `home_timeline_list.dart:1003–1095`、`assignment_card.dart:515, 765–808`、`manual_home_card.dart:234, 438–457` 与 `assignment_store_personal.dart:915–953`，现有实现存在 **4 重叠加缺陷**：
1. **透明命中空洞**：`ReorderableDragStartListener` 内部 `Listener` 默认 `HitTestBehavior.deferToChild`，其子组件 `Tooltip -> SizedBox(34×48) -> Center -> Icon(18)` 未铺透明实心命中层（如 `ColoredBox(color: Colors.transparent)` / `HitTestBehavior.opaque`），手指偏离中间 `18×18` 图标 2–3dp 即穿透至底层 `InkWell` / `ListView`；
2. **边缘手势与侧滑争抢**：拖把宽 `34dp` 且紧贴卡片右缘 `right: 2`（叠加外层 `16dp` 列表边距，右半侧落入 Android `24dp` 预测性边缘返回区），左侧又在 `JournalSwipeTile` 横滑区内部，轻微斜拖易被横滑或外层 `ListView.builder` 截胡；
3. **落盘异步回弹**：`onReorderItem` 仅调 `unawaited(store.reorderPinned(nextActiveKeys))`，而 `_reorderPinned` 需等待 `_run -> _savePins` 完成才更新内存 `_pinned` 并 `notifyListeners()`；拖拽松手首帧会按旧 `_pinned` 渲染导致卡片瞬时回弹，写完后才二次跳回；
4. **测试覆盖真空**：全仓 `test/` 对 `pinned-reorder-*` / `拖动调整置顶顺序` 的 Widget 拖拽交互覆盖数为 **0**（仅有 Store 层 `reorderPinned` 单测）。

**设计铁律**：
- 拖把必须拥有**完整实心命中区**（`width: 44, height: 48` + `ColoredBox(color: Colors.transparent)` + `HitTestBehavior.opaque`），且合理留出与屏幕右缘的呼吸距（不贴死右缘），同时隔离 `Tooltip` 长按与 `JournalSwipeTile` 横滑抢占；
- 拖把在 `ReorderableListView` 内若受 `shrinkWrap: true` + `NeverScrollableScrollPhysics` 嵌套 `ListView.builder` 影响，须通过**先红后绿**的真实 Widget 拖拽测试实证（含中心点与偏心点拖动、普通课业卡与手动待办卡、`largeText` 与 `compactDensity`），确保拖拽松手后即时维持新顺序（支持乐观本地序并在持久化失败/账号切换时自动回滚至真源 `_pinned`），且不破坏 `FB-005` 非置顶区排序、卡片点击与长按菜单。

### 2.2 Dart 大文件深模块拆缝铁律（M4 / M5，沿用 `v1.92.1` 经验）

经全仓静态扫描确认：
- **`ChaoxingLocalClient`** 在 `test/` 中共有 **43 个测试子类**，覆写 **9 个成员**（`cancelActiveRequests`、`clearSession`、`fetchAssignments`、`fetchAssignmentsWithOptions`、`fetchCourseChapters`、`fetchReturnedWork`、`lastFetchedNotices`、`login`、`needsSessionInitialization`），并含 **5 处 `super.` 调用**（`cancelActiveRequests`、`clearSession`、`dio`、`enableClassroomTasks`、`wait`）。
- **`LocalNotificationService`** 在 `test/` 中共有 **59 个测试子类**，覆写 **12 个成员**（`cancelPrivateSchedules`、`inspectHealth`、`isLegacyAssignmentMigrationComplete`、`migrateLegacyManualChannelIfNeeded`、`migrateLegacySummaryChannelIfNeeded`、`readScheduleEvidence`、`removeLegacyAssignmentSchedules`、`rescheduleAssignments`、`rescheduleManual`、`rescheduleSummary`、`retireLegacyUpdatesAndDeadlineChannelsIfNeeded`、`showTestManualNotification`）。

因此 **M4 与 M5 严守以下 5 条铁律**：
1. **公开接口原地保留**：所有公开方法、getter/setter、构造参数、实例字段、静态常量及公开静态方法全部留在主类（`class ChaoxingLocalClient` / `class LocalNotificationService`），公开方法体收缩为 1–3 行薄转发桩，**绝不**将公开方法直接移入 `extension`；
2. **`part` 内部虚分派安全**：`part` 内的私有 `extension` 调用任何可被子类覆写的公开成员时，**必须**调用 `this.<publicMethod>` 而非绕行私有 `_impl`；
3. **纯规则抽独立深模块**：不依赖宿主私有可变状态的纯策略、分类、校验、重试/熔断计算与 ID 分配抽为独立非 `part` 深模块文件（`chaoxing_request_policy.dart`、`notification_schedule_policy.dart`），通过清晰参数/构造接口暴露并配专属单测；
4. **共享契约零变更**：同步失败绝不以空快照覆写旧数据、`9010` 触发即刻暂停同批后续来源、`v3` 有声渠道 ID/铃声/振动/不覆写已建渠道、`ReminderDatabase` 与 `SharedPreferences` 补偿事务顺序与 fail-closed 隐私清理逻辑 100% 保持原语义；
5. **所有 `import` 留在主库文件**，及时清理未使用导入并确保 `dart analyze lib test` 零告警。

### 2.3 小组件自然日差口径一致性（M3）

- 当前首页卡片 `AssignmentCard._compactRemaining`（`assignment_card.dart:116–127`）对 `>= 24h` 统一按 **Asia/Shanghai 北京时间自然日差**（`DisplayPreferences.beijingDayDiff(deadline, now)`）计算；而 `WidgetSnapshotService._remainingText`（`widget_snapshot_service.dart:202–217`）与 Kotlin `AssignmentWidgetTimeText.remainingText`（`AssignmentWidgetProvider.kt:458–478`）均使用 `ceil(hours / 24)` / `ceil(minutes / 1440.0)`，导致次日截止（如今日 09:00 看明日 23:59，剩 39 小时）被错误展示为「2天」。
- 本轮统一 Dart 与 Kotlin 两端逻辑：
  - `< 60 分钟`：保持 `${minutes}分钟`（`ceil` 向上取整，最低 1 分钟）；
  - `< 24 小时`：保持 `${ceil(minutes / 60.0)}小时`；
  - `>= 24 小时`：改按 **`Asia/Shanghai` 自然日差** `dayDiff = ChronoUnit.DAYS.between(nowBeijingDate, anchorBeijingDate)`（Dart 复用 `DisplayPreferences.beijingDayDiff(deadlineAt, now)`）：`dayDiff <= 1` 统一显示 `1天`（或当 `dayDiff == 1` 且 `>= 24h` 时为 `1天` 而非 `2天`，`dayDiff >= 2` 显示 `${dayDiff}天`，避免跨 24h 阈值但仍是明天的任务误报 `2天`）；
  - 保留既有 `examStart` 前缀 `'距开考 '` / `'已开考'`、过期 `'已截止'` 与兜底 `fallback` 语义，并同步覆盖跨午夜、跨月、跨年及多时区（`UTC` / `America/Los_Angeles` / `Asia/Shanghai`）双端单测。
