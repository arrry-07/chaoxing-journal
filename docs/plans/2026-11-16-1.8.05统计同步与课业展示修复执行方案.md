# 1.8.05 统计、同步问题与课业展示修复

基线为已发布 `1.8.04+71`（应用源码 `a4a4b01`），目标 `1.8.05+72`。本轮不移动 `v1.8.04`，不替换 Release `446717018` 的资产，通知无年份时间继续只做只读投影。

## 范围

- FB-001：统计页对无课程键的账号考试强制解包导致灰屏。总览保留全部记录；按课程分区仅使用有课程键的记录，账号考试单独成行。
- FB-002：可信截止已过、来源为课堂任务且提交状态仍未知的记录退出首页当前待办和“待核对课业”，本地记录继续保留。正式作业状态未知仍留在待核对；时间不可信或缺年份不触发历史分流。
- FB-003：同步问题在展示层按阶段、类型、文案聚合，显示去重问题数、受影响课程、数量和下一步操作；原始条目仍可逐条展开。课程考试 PC 列表明确作为补充证据：已完成考试不允许看卷且缺少稳定考试 ID 时，不据此把已成功的手机考试列表判为结构失败；完全没有手机身份时才保留具体失败。
- FB-004：类型筛选收敛为全部／作业／考试；“作业”覆盖正式作业及 35/42/77 课堂活动，已存 `task` 偏好归一为“作业”。
- FB-005：时间双向排序固定三层：未逾期和有可用展示时间在前，无截止／待确认／已完成居中，已逾期始终最后。方向只影响层内时间顺序；中间层按课程与名称排序。`FB-005` 命名回归写入长期约束。
- FB-006：V3 `endTime=0` 不再被当成已确认无截止。已提交且截止未核实的作业读取同一作业详情，使用列表 `startTime` 锚定无年份区间；详情仍失败时只保留上次可信截止，不用 null 覆盖。已提交卡片沿用普通作业结构。
- 性能：为 Store 的当前显示目录建立不可变显示索引，缓存投影、考试源索引、通知区间和展示对象；普通状态通知不重建，数据、预览、关注和账号切换时失效。`now` 派生结果从不缓存。
- 同步诊断：客户端新增课程索引、正式作业、课堂任务、考试与通知的阶段耗时；原有网络／解析采样和整轮耗时保留。
- 真实取证：已提交作业 V3 列表确实返回 `endTime=0` 且详情含可锚定的无年份区间；课程考试失败已定位为 PC 页面“不允许查看试卷”且无 `goTest`，不是手机列表或课程入口结构失败。

## 兼容边界

- 筛选 JSON 结构不变，旧 `task` 值只做读取归一。
- 排序、历史分流和显示索引只作用于展示查询，不改 `deadlineAt`、信任字段、日历、提醒、自动结束与备份 schema。
- `SyncIssue` 持久化结构不变，聚合只在展示层；新阶段耗时为内存诊断，不含账号、课程或访问标识。
- 不新增网络来源；PC 补充失败不得绕过既有身份校验或凭据校验。
