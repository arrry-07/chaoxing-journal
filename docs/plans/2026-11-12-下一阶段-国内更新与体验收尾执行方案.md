## 三、任务A：把免费Gitee从候选变成可用源

### A1. 账户与可见性

- [ ] 用户自己注册/登录。执行者先查看当前可用连接器或用户登录会话，不能扫描其他软件凭据，也不让用户在聊天中粘贴密码/PAT。
- [ ] 找到用户控制的已有合适仓库；无仓库时拟建独立`chaoxing-journal-downloads`分发仓库，只含公开APK/清单/说明，不改变现有GitHub仓库可见性。明确仓库归属、拟公开的文件清单后再由用户确认创建公开分发仓库；不要求提供业务账号资料。
- [ ] 核对当时免费规则、APK附件许可、审核/登录要求、单附件100M及总附件1G是否仍适用。当前57.79MB包满足大小门槛，APK放Release附件，不放Git blob；此事实不等于用户端直链已通过。

### A2. 使用现有正式包做端到端验证

- [ ] 获取已发布1.7.4原始字节，验证大小、SHA-256、签名和身份，上传到明确批准的Gitee分发仓库，不重新签名或覆盖GitHub资产。
- [ ] 通过平台返回的真实附件链接验证匿名HTTPS GET，拒绝登录页、验证码、HTML错误页；先HEAD/小范围GET检查，再完整下载一次并比对上述digest。不能只验证别人仓库的样例。
- [ ] 记录重定向主机及最终Content-Type/Content-Length；Range返回206时核对区间，200时验证现有单流回退。不得在下载脚本或APK中附带上传凭据、Cookie或Referer绕过登录要求。
- [ ] 为两个清单找到固定、匿名、可重新读取的HTTPS地址。优先验证Gitee原始文件URL的真实响应；若返回HTML或需要登录则不采用该路径。Release附件下载路由由平台实际结果确定，不凭猜测拼URL。
- [ ] 每份清单必须验证UTF-8、JSON、64KiB以内、正确MIME/内容、缓存可更新。依现有客户端验证域名和重定向规则；若真实Gitee合法跳转不受支持，先用合成测试复现，只添加最小明确规则，不放开到任意HTTP/内网主机。
- [ ] 关闭开发机任务代理后验证HTTP链路，记录网络条件；这只算该网络证据，不代替后续手机移动数据/宽带验证。

**停止条件：**Gitee要求用户下载时登录/验证、禁止该APK分发、清单无法稳定读取或额度不满足时，免费路线标为未通过，不绕过平台限制。再比较可支持APK的付费托管，总费用含域名、HTTPS、存储、请求与流量；10元预算内也要用户确认开通。

### A3. 复用现有更新器和补齐发布脚本

涉及文件（相对仓库根）：`scripts/update-manifest.ps1`；Flutter下`lib/src/services/app_update_service.dart`、`app_update_controller.dart`；已有相关测试。先读代码，不将以下名字误认成现有新接口。

- [ ] 现有编译配置已支持`UPDATE_STABLE_MANIFEST_URL`、`UPDATE_MANUAL_MANIFEST_URL`和旧`UPDATE_MANIFEST_URL`，现有AppUpdateInfo已支持备用URL。只配置验证过的地址，不重写双通道和下载事务。
- [ ] 现有脚本根据BaseUrl拼`/<versionCode-versionName>/<apkName>`；Gitee路由未必符合该结构。先读脚本实际versionKey，增加可选`-ApkUrl`显式HTTPS附件地址；未提供则保持BaseUrl行为。验证URL无内嵌凭据，不能取消签名、版本、大小或上一版本校验。
- [ ] 先为脚本补有效显式URL、旧BaseUrl兼容、HTTP/凭据URL拒绝、错误签名/身份的有效检查，再实现最小修改。若PowerShell参数绑定需要调整，保持旧命令仍可运行，拒绝两种输入均缺失。
- [ ] 如需新增`publish-gitee-update.ps1`，默认只生成部署清单和执行预检，外部上传需显式执行参数；认证由受保护环境提供，禁止日志输出。平台API不支持的步骤保留人工上传，不编造API。
- [ ] 发布顺序固定：唯一版本APK→匿名回下载校验→manual清单→符合迭代策略时stable清单→匿名重新读取清单验证。复用现有脚本判定，当前1.7.4作为镜像基线无需伪造一条更高版本。
- [ ] GitHub可为同哈希APK备用；主源检查不能先等GitHub超时，两个清单主源都不可依赖GitHub API。源失败不能把校验失败当成功。
- [ ] 首个配置国内源的新包需要用户通过Gitee网页手动覆盖安装；已安装旧包不会因上传Gitee自动学会新地址。给出明确迁移页和同签名升级说明。

### A4. 免费容量保留策略

- [ ] 不承诺无限存历史。57.79MB包在1GB总额度下只能容纳约17份，且还要留其他附件和平台计量余量；建议默认保留最新8份不同APK，超过时先输出待清理清单，不自动删除。
- [ ] 不删除当前stable/manual、备用源或仍被迁移说明引用的文件；清理前更新引用并由维护者确认。GitHub所有历史标签/正式资产保持原样，不以节省Gitee额度为由删GitHub历史。
- [ ] 记录全部镜像版本、字节数、摘要、公开URL、上传时间，达到80%容量先提示。别创建多账号/多仓库规避平台限制。
