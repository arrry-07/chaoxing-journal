## 3. 目标与非目标

### 目标（可判定）
1. **M1 本学期课程筛选精准化**：首页搜索筛选「课程筛选」弹层中的「本学期」仅展示具有本学期正向证据的课程（手动标本学期、目录匹配本学期、本学期时间窗内有可信作业/考试/人工通知、本学期增量同步拉取到新作业、有效补修召回、或当前首页存在可见课业/关联手动待办）；无目录且无本学期活动的静默课分流至「未分组」筛选项（同时保留其同步扫描资格避免漏扫新开课）；收紧往期课程的超远期未来截止误召回；扩展明确年份目录正则的容错性。
2. **M2 逾期暖琥珀黄去红降噪与首页卡片排版重构**：在 `JournalPalette` 新增浅/深双主题 WCAG AA（>= 4.5:1）暖琥珀逾期色与暖灰墨标题色；首页逾期卡片去掉冗余「已截止」行、硬边框与 `⚠` 图标，改用暖琥珀柔底标与暖灰墨标题；同步切换统计页「已逾期」标与饼图逾期扇区颜色；重构 `ManualHomeCard` 彻底隐藏首页正常「提前30分提醒」文案与铃铛图标、**保留「自己添加」**轻标、将倒计时收进左轨并保持与 `AssignmentCard` 左轨宽度对齐、将非备注辅助项合并单行并将用户备注独立为柔和手帐引用条；同步将 `AssignmentCard` 非置顶倒计时收进左轨。
3. **M3 待办详情页「备注」与页面精修**：修复 `JournalGroupedCard` + `ManualEntryDetailScreen` 备注卡片 70dp 胖头部，与上方「安排详情」40dp 头部严格齐平，将「复制」改为轻量次级胶囊（保留充足触控区）；将「安排详情」底部的「查看提醒状态」改为卡片内带顶部分割线的标准 `JournalGroupTile`；移除顶栏右上角重复的铅笔编辑按钮，保留底部等大「编辑 / 删除」双按钮。

## 7. Stage 1 元步骤

### M1 · 本学期课程筛选精准化与未分组隔离

- **前置依赖**：无。
- **1. 精确位置**：
  - `study_assistant-1.1.0/local_app/lib/src/services/course_term_catalog.dart`：`AcademicTerm._spanFolderPattern` / `_singleYearFolderPattern` / `tryParseFolderLabel`、`CourseTermEntry`、`CourseTermCatalog.build`、`matchesCoursePickerScope`、新增 `matchesHomeCoursePicker` 与 `isUngroupedCourse`。
  - `study_assistant-1.1.0/local_app/lib/src/services/assignment_store.dart`：`termCatalog` getter（约 L1573–1590）及更新 `_changes` 后清理 `_termCatalogCache`。
  - `study_assistant-1.1.0/local_app/lib/src/features/assignment_list_screen.dart`：`_openFilters` 内课程筛选 `showJournalPickerSheet`（约 L2490–2541）。
  - `study_assistant-1.1.0/local_app/lib/src/features/course_list_screen.dart`：`_buildCourseSubtitle` 与学期管理区快捷操作（约 L312–413）。
- **2. 具体改法与逻辑边界**：
  1. **目录名宽松匹配（`AcademicTerm.tryParseFolderLabel`）**：
     - 保留严格起止全匹配逻辑优先；若未命中，增加带前后缀容错匹配（允许目录含前缀如 `我的课程/`、后缀如 `必修`/`选修`/`课程`/`课表`，例如 `2025-2026(1) 必修`、`2026年秋季课程`、`大二上(2026秋)`）。
     - 校验硬边界：跨年区间必须满足 `end == start + 1` 且年份在 `2000..2100`；若同一字符串中命中多个不同学期则拒绝返回 `null`；无年份相对年级词（`大二上学期`、`大一下`、`专业核心课`、`期末冲刺文件夹`、`2024-2026(1)`）必须仍返回 `null`。
  2. **增量新作业拉取证据（`CourseTermCatalog.build`）**：
     - 新增可选参数 `Iterable<AssignmentChange> changes = const []`（默认空集合保持所有现有调用方源码兼容）。
     - 构建 `publishedChangeTimesByCourse`：遍历 `changes`，仅取 `kind == AssignmentChangeKind.published` 且对应 `assignmentId` 能解析出有效 `courseKey`（通过传入 `assignments` 映射或 `Assignment.inferSource` 解析 `cx:work:<courseId>:<clazzId>:` / `cx:activity:<courseId>:<clazzId>:` / `cx:exam:<courseId>:<clazzId>:`）且 `!hiddenAssignmentIds.contains(change.assignmentId)` 的记录；若该 `assignment` 存在明确早于本学期的可信截止/开考时间则不作为本学期新作业；否则将其 `change.at.toUtc()` 纳入该课程的 `trustedActivityTimes` 与（当 `AcademicTerm.fromInstant(change.at) >= currentTerm`）`recallSignals`。
  3. **收紧往期课程召回（`recallSignals`）**：
     - 常量 `static const Duration maxFutureRecallHorizon = Duration(days: 180);`。
     - 原逻辑 `resolved.at.toUtc().isAfter(now.toUtc())` 改为：仅当 `resolved.at.toUtc().isAfter(now.toUtc())` 且 `!resolved.at.toUtc().isAfter(now.toUtc().add(maxFutureRecallHorizon))` 时计入未完成未来截止召回（考试开考时间同理限制在 `<= 180` 天内）；本学期内可信 `publishedAt` / `availableFromAt` / 本学期人工 `CourseNotice` / 本学期增量 `published` 变更不受 180 天限制，依然正常触发召回。

1. **Commit 列表**：按顺序列出本次所有 commit（完整/短 SHA + 信息），并**单列标记临场修复 commit**；
2. **元步骤完成矩阵**：`M1`–`M6` 逐项状态（已完成 / 未完成）；
3. **门禁与测试结果**：`dart format`、`dart analyze`、定向/全量 Flutter 测试精确通过数与失败数、Python 门禁结果；
4. **证据指针**：`origin/dev` 最新 commit SHA、对比链接、如产生测试日志则附路径；
5. **未完成项与不确定点**：明确列出任何未能自动验证或需 Gate / 维护者重点确认的点（无则写“无”）。
