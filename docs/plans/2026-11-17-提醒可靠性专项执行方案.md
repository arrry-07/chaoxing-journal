## 3. 阶段一：建立失败回归并实施三项修复

本阶段解决具体失败条件，保留现有时间规则、通知隐私、账户隔离和有效旧提醒。

### R1：系统通知查询失败时，仍能安全撤销明确失效的个人提醒

起点是[当前事务归属校验](../../study_assistant-1.1.0/local_app/lib/src/services/local_notification_service.dart)中的 `_verifyV2JournalOwnership`。前面的清理容忍已投递列表查询失败，后面的恢复却再次依赖它，阻断实际取消。

实施规格：

1. 将现有忽略目录探针整理为正式回归，先确认旧实现失败。
2. 保留现有类别串行队列和持久 journal。对 **manual 类别、committed 阶段**增加有限的归属证明降级：
   - 待投递列表读取成功；
   - 每个准备取消的 ID 都有明确、合法的 `p:` payload；
   - 其他类别清单可读，且不存在 ID 归属冲突；
   - 仅已投递列表查询失败。
3. 满足上述条件时，允许撤销这些已证明归属的待投递提醒；不得用一个宽泛 `catch` 跳过整个归属检查。
4. 待投递查询失败、payload 缺失、归属冲突或取消对象证据不足时，保留恢复记录和警告，不猜测删除。
5. 取消失败继续保留 journal；接口恢复后可完成重试。新排程失败仍保留其他有效旧提醒。
6. “已取消可确认的待投递提醒”和“系统可见通知完整性未确认”分别报告，不能显示为全部清理成功。
7. 不放宽旧版 journal、其他通知类别及隐私清理的既有保护。

### R2：凌晨延迟及领取后跨午夜，不丢失尚未开始同步的机会

起点是[Worker 的领取顺序](../../study_assistant-1.1.0/local_app/android/app/src/main/kotlin/com/example/studyassistant/FlutterCheckWorker.kt)。

实施规格：

1. **领取前检查实际时间和冷却资格。** 夜间或冷却未结束时，不领取信号、不启动 FlutterEngine；保留一个延迟后继。白天窗口继续为设备本地时间 `08:00—00:00`，不更改个人日程规则。
2. 继续在启动引擎前持久化领取，保留防止同信号失败循环的机制。
3. 为“领取后恢复会话跨午夜”增加明确回执：
   - `BackgroundCheckResult` 新增可空 `skipReason`，窗口拒绝使用固定值 `outsideWindow`。
   - 后台 `finished` 消息透传该字段，不解析中文提示文本。
   - 外层窗口检查，以及等待租约后、首次远端课业请求前的内层窗口检查，都必须保留该结果，不能经 `Future<void>` 丢失原因。
4. 用内部、绑定当前操作及账户代次的同步结果传播跳过原因。公开的 `syncAssignments()`、`syncAssignmentsForTrigger()` 仍保留 `Future<void>` 包装，避免改变现有调用合同。
5. 通知监听的顺延时间独立计算，不能依赖“白天定期检查已开启”；关闭定期检查、监听开启时仍可顺延。
6. 仅对及时收到、未停止、本次唯一结算的 `success=false + skipped=true + skipReason=outsideWindow`，允许撤回本次“未开始远端课业同步”的领取。
7. 普通失败、超时、取消、崩溃、未知回执和已经开始远端读取的退出，不获得回退权限。

为防止迟到回执撤销新领取，新增内部接口：

| 拟新增接口／类型 | 合同 |
|---|---|
| `NotificationSignalClaim` | 保存账户、epoch、领取版本、唯一 token、领取时间及事务内捕获的旧尝试状态。旧值只留 Native 内存。 |
| `claimNotificationAttempt(...)` | 原子领取最新可领取版本并保存唯一 token；旧 `Long?` 接口保留兼容包装。 |
| `ensureDeferredNotificationSuccessor(...)` | 确认本账户／epoch 的延迟后继已持久入队，或已有有效后继可复用；不能把当前 RUNNING 自身当作后继。 |
| `rollbackUnstartedNotificationAttempt(claim)` | 条件更新：账户、epoch、token、领取版本、时间、pending 和 consumed 均符合本次领取快照时，才恢复旧尝试状态。 |

执行顺序必须是：**确认后继入队成功 → 条件回退领取 → 返回正常 Worker 结果。** 入队失败或结果未知时不回退。

数据库从 v4 增量升级到 v5，仅增加可空 claim-token 字段；保留全部既有数据，覆盖 v3→v5 连续升级。账户切换及相关会话重置应清理失效 token。不得使用毫秒时间或通用 `mutationVersion` 代替唯一 token。

### R3：消除排队转运行时被 REPLACE 取消的竞态

调度策略固定为：

| 观察状态 | 行为 |
|---|---|
| 无任务／已有排队任务 | 使用 `KEEP` 入队 |
| 正在运行且无后继 | 使用 `APPEND_OR_REPLACE` 追加一个后继 |
| 正在运行且已有后继 | 合并，不追加 |

补充要求：

- 排队期间新信号只更新数据库；Worker 开始时原子领取最新版本。
- 不因新信号取消已有任务，不把所有入口统一改成 KEEP。
- 收尾时无论业务成功失败，都检查 `pending > max(consumed, attempted)`，只为尚未尝试的更高版本补排。
- 成功只消费本次领取版本；业务失败仍返回 WorkManager 的正常完成结果，避免框架失败传播阻断有效后继。
- 启动时重新检查窗口和冷却；不能认为排程时合法就代表实际执行时合法。
- 保留 60 秒合并及 10 分钟冷却，正常路径不增加重试次数。

## 4. 阶段二：自动化与实际收提醒验收

本阶段证明修复后的外部行为，不以“排程成功”替代“系统通知已出现”。

### 自动化必测

| 范围 | 必须覆盖 |
|---|---|
| 个人提醒撤销 | 删除、完成、关闭提醒；已投递查询持续失败；待投递查询失败；跨类别冲突；取消失败；重启恢复；其他有效旧提醒保留。 |
| 时间窗口 | 白天排程、凌晨实际启动；午夜前领取、恢复后跨午夜；等待租约后跨午夜；08:00 边界；定期检查关闭而监听开启；上海及洛杉矶时区。 |
| 领取回退 | token 只能回退一次；旧 token、迟到回执、超时、账户变化、新 pending／consumed 状态均不能错误回退；后继入队失败不释放领取。 |
| 队列竞态 | 状态读取后 QUEUED 转 RUNNING；新信号不取消原任务；排队 UUID 保留且领取最新版本；运行中新信号仅一个后继；失败不自续接；收尾交接时到达的新信号仍可处理。 |
| 数据与兼容 | v4→v5、v3→v5 保数据；旧领取接口调用方；账户隔离；通知详情关闭；完成、隐藏和取消关注后的资格失效。 |

测试方法固定：

- Native 与 Dart 使用可注入时钟，不等待现实午夜。
- 用 latch／可控 Executor 固定竞态顺序，不靠反复运行碰运气。
- 保留 WorkManager `2.12.0`；若测试使用框架调度驱动，仅增加同版本 `work-testing` 测试依赖，不改生产初始化方式。测试时钟仍需单独控制。
- 把当前“排队任务 UUID 必须被替换”的旧断言改为正确合同。
- 每项先获得旧实现失败证据，再报告修复通过。

开发阶段只跑对应 Dart、JVM 及仪器测试。最终冻结后运行一次全量 Flutter、分析、格式／元数据、双时区、原生检查、Gradle 单测、仪器编译及 lint；实际运行相关仪器测试，不能只编译。保留 `FB-005`、课业分组和通知隐私回归。

### MuMu 实际收提醒矩阵

使用隔离 QA 实例及现有通知设备探针，测试数据不包含真实凭据；探针包与正式包分开标识。

| 场景 | 通过条件 |
|---|---|
| 新作业 | 首次基线不刷历史提醒；之后发现合成新作业，经生产规划及发布链路形成一条实际系统通知，重复同步不重发。 |
| 截止提醒 | 已安排可信截止后断网，系统通知仍出现；完成、隐藏或取消关注后不再发出失效提醒。 |
| 个人日程 | 按现有提前 30 分钟规则实际投递；删除／完成／关闭提醒后撤销。故障注入只拦截查询接口，其余调用走真实系统插件。 |
| 后台与恢复 | 切后台、锁屏、正常进程结束及隔离实例重启后验证恢复。系统“强行停止”单独记录，不写成仍应必达。 |
| 点击 | 从系统通知实际点击，进入对应记录；记录不存在或账户变化时安全回到适当入口。 |
| 通知触发同步 | QA 中同时满足应用开关及系统授权，以合成信号验证调度和去重；自然官方通知保持独立的未覆盖项。 |

每次记录目标时间、实际展示时间、通知类别、点击结果、撤销结果、APK 哈希及设备。明确区分真实系统展示、合成数据、故障注入与自然官方事件。

最终正式包在原“学习通”实例保数据覆盖，核对首次安装时间、登录态、课程及课业数量。可通过一个唯一命名的临时个人日程完成正式包收提醒烟测，结束后只清理本次测试项，并恢复验收前设置。当前真实数据若有变化，按新快照核对，不硬编码旧数量。
