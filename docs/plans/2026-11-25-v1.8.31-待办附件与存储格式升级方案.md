## 3. 目标与非目标

### 目标
1. 先升级待办存储格式（`PersonalWorkspace.map` 支持显式 `optionalKeys`；新增 `ManualAttachment` 模型；`ManualEntry` 增加 `updatedAt` 与 `attachments`；`StudyNotebook` 本地读写兼容 v1/v2），确保**加密备份与便携导出继续严格输出 v1 + 10 键**，旧版本可无损解密并读取待办文字与日程。
2. 扩展 `PersonalFileBridge` 与 `update_file_paths.xml`，通过系统相机 Intent（无 `CAMERA` 权限）、Android 13+ Photo Picker / 旧版 `ACTION_OPEN_DOCUMENT` 与文件选择器将照片/文件**流式复制到应用私有目录 `filesDir/manual_attachments/`**（拍照临时文件落 `cacheDir/camera_captures/` 用毕即删），执行路径白名单与单文件 20 MB 硬上限。
3. 在编辑器 `ManualEntryEditor` 实现「拍照 / 相册 / 文件」三入口、每条最多 9 张图 / 最多 20 个附件 / 单文件 `<= 20 MB` 拦截提示、草稿取消/替换/保存差集安全清理；在详情页 `ManualEntryDetailScreen` 展示图片缩略图网格、全屏缩放预览与系统打开文件；在 `ManualHomeCard` 展示 `附件 N` 指示。
4. 在 `AssignmentStore` 补齐保存差集、登出、切换账号时的附件文件清理（复核 `restoreBackupSnapshot` 仅补缺、不误删本地已有附件）；在 `BackupScreen` 明确披露加密备份不含本地附件文件。

### 非目标
1. 不在本轮实现 WebDAV 云同步（仅预留 `ManualEntry.updatedAt` 字段）；
2. 不修改既有 `PersonalFileBridge` 请求码 `6183` 与 `PersonalWork.files` (`content://`) 逻辑；
3. 不申请 `android.permission.CAMERA` 或 `READ_MEDIA_*` / `READ_EXTERNAL_STORAGE` 权限；
4. 不将大体积附件字节打进 `BackupSnapshot` / `SharedPreferences` JSON。

## 4. 已定决策

| # | 决策 | 理由 | 被否方案 |
| --- | --- | --- | --- |
| D1 | 加密备份（`BackupSnapshot`）对 `StudyNotebook` 与 `ManualEntry` 强制走 `portable: true`，严格输出 `version: 1` 与旧版 10 键 | 旧版本 `BackupSnapshot.decode` 经 `PersonalWorkspace.map` 精确校验键集合与 `version == 1`，便携剥离后旧版本可直接读待办与日程 | 升级备份 `schema 10` 或保留新键（会导致旧版拒读） |
| D2 | 附件文件复制到 `filesDir/manual_attachments/<id_sanitized>` 并持久化轻量元数据 | 避免系统相册/Document URI 失效或权限回收；应用卸载/清数据自动随私有目录清除 | 长期保存第三方 `content://` URI |
| D3 | 拍照用 `FileProvider` 写入 `cacheDir/camera_captures/`，不申请 `CAMERA` 权限 | 系统相机 Intent 免权限且兼容 API 26–35；拷贝后 `finally` 清理临时缓存 | 在清单申请 `android.permission.CAMERA` |

| D5 | 路径白名单策略独立抽取到 `ManualAttachmentPathPolicy.kt` 与 `ManualAttachment` 模型并双端对称校验 | 方便 JVM 单测覆盖路径穿越、`..`、反斜杠、20 MB 上限与超长路径，且不依赖真机即可验证 | 在 `Activity` 内联字符串拼接 |

## 7. Stage 1 元步骤

### M1 · 存储格式向后兼容升级
1. **精确位置**：`personal_workspace.dart` (`PersonalWorkspace.map`)；新建 `manual_attachment.dart`；`study_notebook.dart` (`ManualEntry`、`TermArchive`、`StudyNotebook`)；`backup_snapshot.dart` (`create`、`encode`、`decode`)。
2. **具体改法与边界**：
   - `PersonalWorkspace.map(dynamic v, Set<String> keys, {Set<String> optionalKeys = const {}})`：校验 `v is Map`、`keys.every(v.containsKey)`、且 `v.keys` 全部属于 `keys ∪ optionalKeys`；默认 `optionalKeys = const {}` 行为不变。
   - `ManualAttachment`：常量 `maxImagesPerEntry = 9`、`maxAttachmentsPerEntry = 20`、`maxFileBytes = 20 * 1024 * 1024`、`storagePrefix = 'manual_attachments/'`、`maxRelativePathLength = 260`。校验 `id`、`kind` (`image`/`file`)、`name`、`relativePath`（仅允许 `manual_attachments/` 下合法安全分段，禁 `..`/`\`/前导 `/`）、`mimeType`、`sizeBytes` (`0..maxFileBytes`)、`addedAt` (`notebookDate` 严格 UTC ISO8601)。
   - `ManualEntry`：增加 `DateTime? updatedAt` 与 `List<ManualAttachment> attachments = const []`；`copyWith` 完整覆盖新字段与 `clearUpdatedAt`；`completed(bool value, {DateTime? now})` 保留 `attachments` 并更新 `updatedAt`；`toJson({bool portable = false})` 在 `portable: true` 时仅输出旧版 10 键；`fromJson(dynamic v, {bool portable = false})` 在 `portable: true` 时仅允许严格 10 键，否则允许 `{updatedAt, attachments}` 并校验图片 `<= 9`、总附件 `<= 20`、`id` 与 `relativePath` 唯一。
   - `TermArchive`：保持 `TermArchive.fromJson` 默认 1 参兼容或用显式 lambda 调用并透传 `{bool portable = false}`；`TermArchive.capture` 剥离 `attachments`。
   - `StudyNotebook`：保持 `factory StudyNotebook.decode(String raw)` 1 参签名不破坏现有 tear-off，并新增 `static StudyNotebook decodePortable(String raw)`；`toJson({bool portable = false})` 当 `!portable` 且条目使用 `updatedAt` 或非空 `attachments` 时写 `version: 2`，否则写 `version: 1`。
   - `BackupSnapshot`：在 `create`、`encode`、`decode` 中分别调用 `.toJson(portable: true)` 与 `StudyNotebook.decodePortable(...)`。
3. **耦合联动点**：检查 `assignment_store.dart` 与 `local_assignment_repository.dart` 所有 `StudyNotebook.decode`、`encode()` 调用无破坏。
4. **保留行为与反例**：`ManualEntry(...)` 保持可用于 `const` 上下文；任何越界路径、>20 MB、>9 图、>20 附件、重复 `id`/路径或便携 JSON 含未知键全部抛 `FormatException`。
5. **验证**：先写 `manual_attachment_storage_test.dart` 与扩展 `study_notebook_test.dart`，跑绿后进入 M2。

### M2 · Android 原生桥接、FileProvider 路径与路径安全策略
1. **精确位置**：新建 `ManualAttachmentPathPolicy.kt`、`ManualAttachmentPathPolicyTest.kt`；修改 `update_file_paths.xml`、`PersonalFileBridge.kt`、`test/android_manifest_test.dart`。
2. **具体改法与边界**：
   - `ManualAttachmentPathPolicy.kt` 校验 `isValidRelativePath`、`resolveTargetFile(filesDir, relativePath)`（使用 `canonicalPath` 前缀判定防目录逃逸）、`isAllowedSize(bytes)`（`<= 20 * 1024 * 1024`）、`sanitizeDisplayName` 与 `buildUniqueRelativePath`。
   - `update_file_paths.xml` 保留 `<cache-path name="update_apks" path="updates/" />`，新增 `<cache-path name="camera_captures" path="camera_captures/" />` 与 `<files-path name="manual_attachments" path="manual_attachments/" />`。
   - `PersonalFileBridge.kt` 保留 `6183` 不变，新增请求码 `6184` (`capturePhoto`)、`6185` (`pickImages`, `maxCount` 1..9)、`6186` (`pickAttachmentFile`)，以及 `getAttachmentRoot`、`openAttachment`、`deleteAttachmentFiles`、`deleteAllAttachments`。所有流式拷贝放后台 `ExecutorService` 线程执行，按缓冲区累计字节超过 `20 * 1024 * 1024` 立即关闭并删除半成品文件返回 `file_too_large`（`pickImages` 若某张超限或无效做清晰结果返回并确保不留残片）；`capturePhoto` 的 `cacheDir/camera_captures/` 临时文件在 `finally` 与 `close()`/`onActivityResult` 异常路径全清理；使用原生通道回主线程回复 `MethodChannel.Result`。
3. **耦合联动点**：`MainActivity.onActivityResult` 与 `onDestroy -> personalFileBridge.close()` 继续透传给 `PersonalFileBridge`。
4. **保留行为与反例**：严禁引入相机/存储运行时权限；`pick` (`6183`) / `open` / `releaseAll` 行为完全不变。
5. **验证**：更新 `android_manifest_test.dart`；拷贝至 ASCII 目录运行 `.\gradlew.bat --no-daemon :app:testDebugUnitTest :app:compileDebugAndroidTestKotlin :app:lintDebug --rerun-tasks`。
