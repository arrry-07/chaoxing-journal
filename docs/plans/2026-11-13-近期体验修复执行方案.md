# 近期体验修复执行方案

> 执行者按任务逐项实现、验证和提交；可使用 executing-plans 或按文件归属分工。复用当前工作区，先确认 Git 与工程状态，不覆盖既有修改。

**目标**：改善作业打开、系统设置、更新弹窗、通知识别及期限筛选；将依赖外部系统的功能留在长期路线图。

**实现方式**：沿用 Flutter 页面、现有 MethodChannel 与 Android 公开 Intent。五项独立验收，不重构同步、账号和提醒架构。

**技术栈**：Flutter/Dart、Android Kotlin/Java、Android XML drawable、现有 Flutter/JVM/instrumented 测试。

**需求依据**：维护者 2026-11-13 本轮九项反馈；长期任务及阶段门槛见[路线图](../ROADMAP.md#long-term-phases)。本方案已执行并发布为 `1.7.51+58`，实际结果以[验收与发布记录](../reviews/2026-11-13-1.7.51近期体验修复验收与发布记录.md)为准；下方步骤保留执行时的验收设计。

## 当前基线与全局约束

- 勘察基线：`codex/startup-update-prompt` / `830405c`；源码仍为 `1.7.5+57`。1.7.5 已发布，启动补丁提示修复已提交到该分支，尚未包含在正式 APK 中。
- 下一正式小版本按维护者约定使用 `1.7.51`，后续 `1.7.52`、`1.7.53`；不是对三段字符串做浮点加法。Android versionCode 独立递增，当前下一候选为 58，冻结前重新检查远端占用。
- 开发和纯文档更新不反复升版；冻结发布候选时统一升一次。版本一旦递增，必须完成对应正式 APK、GitHub Release、校验文件与下载文档交付，不能只留源码版本。
- 启动可提示更新，保留忽略版本，不自动下载或安装。1.7.5 的旧 major/minor 过滤无法远程改变，同 minor 升到 1.7.51 首次需要手动检查或网页覆盖；更早客户端能否启动发现须按其实际规则核对，不能一概而论，也不能声称旧客户端自动获得修复。
- 保留包名、签名、猫头像、用户渠道偏好和现有数据；不清空已登录模拟器。物理设备须维护者连接并确认后才操作。
- 编号沿用反馈原编号；近期 P1–P5 是本组顺序，长期 P1–P4 是长期组顺序，不作为已证实缺陷严重性的标签。

## 任务 1：作业原生入口可行性与打开体验

**实际情况**：`ExternalLinkService.openAssignment(String)` 已调用原生 `openChaoxingAssignment`；`ChaoxingAssignmentLink.java` 用分享回跳协议把原始签名 URL 交给学习通。历史记录在学习通 7.0.6 验证过 App 内 WebView，不等于原生作业页，也不能代表当前版本仍一致。`browser` 枚举存在不代表当前会自动兜底浏览器。

**涉及文件**（应用根目录均为 `study_assistant-1.1.0/local_app`）：

- `lib/src/services/external_link_service.dart`、`assignment_web_link.dart`：启动结果、URL 校验。
- `android/app/src/main/java/com/example/studyassistant/ChaoxingAssignmentLink.java`：链接构造。
- `android/app/src/main/kotlin/com/example/studyassistant/MainActivity.kt`：导出处理器检查与打开。
- `lib/src/features/assignment_list_screen.dart`、`assignment_detail_screen.dart`：两处按钮与结果提示。
- 回归：`test/external_link_service_test.dart`、`assignment_web_link_test.dart`、`assignment_detail_navigation_test.dart`，以及 `tool/android_upgrade_probe/NativePoliciesTest.java` 的现有链接策略用例。

- [ ] 先读参考实现 `fetch_homework`、`fetch_homework_detail`、`is_homework_pending`；确认 URL 来自平台，保留签名串，不能凭 workId 自造可执行入口。
- [ ] 在已获授权的学习通环境记录客户端版本，选两份不同课程作业，分别从官方课程内和助手打开；核对前台包、页面实际标题/课程/作业身份、是否跳出 App。不记录完整签名链接、Cookie 或题目隐私。
- [ ] 只验证有来源的公开 Deep Link/导出 Intent；能够解析/启动不等于进入正确作业。研究先限半个工作日，无可验证入口即提交结论，不承诺原生页面必达。
- [ ] 有有效入口：先补链接编码、目标身份、未安装/未登录、处理器缺失和启动异常测试，再修改链接构造与原生桥。接口仍使用现有 `openAssignment(String)` 和结果类型，不把“启动成功”当作“作业提交成功”。
- [ ] 无有效入口：保留学习通内置页面；按钮/说明明确“在学习通内打开作业”，保留用户主动选择的网页入口。失败留在助手，禁止静默打开外部浏览器；优化解释，不声称已修成原生直达。
- [ ] 返回助手仍只复核目标课程；复核失败保留状态和提醒。两份作业身份均匹配才算直达通过；无法取证就登记未验证。

## 任务 2：电池设置定位本应用

**实际情况**：`MainActivity.openBatterySettings()` 直接打开 `ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS` 全应用列表，却返回 `DIRECT`。当前 Manifest 没有申请电池优化豁免权限；不能仅给列表 Intent 加 package 就承诺自动选中。

**涉及文件**：`MainActivity.kt`、`lib/src/services/permission_settings_service.dart`、`lib/src/features/reminder_settings_screen.dart`、`reminder_health_screen.dart`；回归 `test/permission_settings_service_test.dart`、`reminder_settings_screen_test.dart`、`reminder_health_test.dart`，必要时补原生 Intent 分支测试。

- [ ] 先补回归：打开本应用详情返回 `appDetailsFallback`；仅列表可用返回 `listFallback`；全部失败返回 `unavailable`；系统取消不等于已设置。
- [ ] 默认先用 `ACTION_APPLICATION_DETAILS_SETTINGS` + `package:<当前包名>` 定位本应用，用户再进入“电池/后台运行”；标题调整为“本应用电池与后台设置”。这能免去寻找应用，但不冒充所有厂商的一步电池页。
- [ ] 本应用详情无法启动时回退标准电池优化列表并提示应用名称；所有分支用真实 `SettingsOpenResult`，不得把列表记成 direct。
- [ ] 本批不新增豁免权限、不硬编码厂商私有 Activity。直接豁免请求留作独立评估；若后续采用，必须验证平台条件、用途与用户主动确认，不能启动时强制申请。
- [ ] 返回前台重新读取真实健康状态；读取失败显示未知/上次结果，不能因“打开设置成功”显示后台已放行。
- [ ] 验收 API26、31 和当前 API35 的处理器可用/缺失情况；至少实际点击验证一台可用环境，其余未测厂商明确记录。

依据：[Android Settings 公共 API](https://developer.android.com/reference/android/provider/Settings#ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS)。直达豁免请求与全局列表是不同入口，前者有权限要求。

## 任务 4：通知图标统一识别

**实际情况**：原生 `AssignmentNotificationPublisher` 和插件初始化均引用 `drawable/app_icon`，该文件只是绿色实心圆角矩形；桌面是猫头像。问题是图形内容，而非两套通知路径分别用了不同名称。

**涉及文件**：`android/app/src/main/res/drawable/app_icon.xml`；仅在确有需要时改 `AssignmentNotificationPublisher.kt` 和 `lib/src/services/local_notification_service.dart`；回归 `test/local_notification_service_test.dart`、`notification_ordering_test.dart` 及 `androidTest/.../AssignmentNotificationPublisherTest.kt`。

- [ ] 把 `app_icon.xml` 改为猫头像的简化单色透明底轮廓，采用 VectorDrawable；保留现有资源名，避免旧排程保存的资源名失效。桌面猫图 PNG 不更换。
- [ ] 原生截止/新增、插件个人待办/摘要/测试通知均核对引用；不改 channelId、不删重建渠道，不触碰用户声音/振动选择。
- [ ] 分别发真实的隔离测试通知，检查状态栏与通知展开栏、浅深色和锁屏；不能只用 XML/引用字符串断言证明显示清晰。
- [ ] 系统小图标与彩色桌面图标统一猫形识别，不承诺像素/颜色完全一致；不直接塞彩色 Launcher PNG 作为 smallIcon。

依据：[Android 通知构建与 smallIcon](https://developer.android.com/develop/ui/compose/notifications/create-notification)。状态栏小图标与桌面启动图标分开使用。

## 任务 5：“无截止”与“未截止”分开处理

**建议决策**：新增“未截止”，原“无截止”明确为“无截止日期”。两者并存，不把现有 `noDeadline` 偏好改成另一种含义。

**涉及文件**：`lib/src/models/home_filters.dart`、`lib/src/services/assignment_query.dart`、`lib/src/features/assignment_list_screen.dart`；按显示文案检查 `calendar_screen.dart`。回归 `test/assignment_query_test.dart`、`home_filter_persistence_test.dart`、`calendar_scope_test.dart`。

- [ ] 新增 `AssignmentDeadlineFilter.notExpired`，序列化为独立名称；旧 `noDeadline` 解码/账号隔离/排序仍有效，不做索引迁移。
- [ ] `filterHome(..., now: now)` 中“未截止”要求：现有可见且未完成范围内、平台待提交状态已确认、截止可信、读取未失败、deadlineAt 非空且严格晚于 now；到达截止瞬间即不属于未截止。
- [ ] “无截止日期”仍表示状态/截止读取可信且 deadlineAt 为空；“待确认”继续收纳读取失败、截止不可信或提交状态未确认，不能混入未截止。
- [ ] 先补固定 now 的边界用例：未来、过去、恰好 now、可信空值、失败但保留旧未来日期、状态不确定、已完成；再实现枚举/查询/标签。
- [ ] 回归搜索和课程组合、偏好重启恢复/账号切换、未知枚举回退、日历两个临时范围；范围入口不会覆盖首页已保存筛选。夏令时及不同时区按绝对时刻比较。
