### 架构与实现决策（执行 AI 不得重新取舍）

- **D1：`_savePins` 签名改为 `Future<bool>`，明确返回「磁盘是否已提交」**
  - 决策：`savePinnedAssignments` 正常返回 → `true`；`LocalStorageLeaseReleaseException`（`local_assignment_repository.dart:1133-1138` 保证 `primaryError == null`，数据已写盘仅租约释放未确认）在仍属当前会话时追加 `_recoveryWarnings` 后返回 `true`；`StaleSessionWriteException` 返回 `false`（静默拒写，不设 `_error` 与 `_recoveryWarnings`）；其余异常照常向上抛出。
  - 理由：与 `saveHomeFilters`、`acknowledgeDeadlineChange`、`_mutateCourseworkState`、`_mutateCourseTermPreferences` 等同文件其余 10+ 写入口保持一致，不触发误报错误文案（守住 `concurrency_isolation_1825_test.dart` S2 约束），`assignment_store.dart` 净增仅约 15 行（符合大文件止增纪律）。
  - 被否方案：① 在 `_savePins` 中 `rethrow` `StaleSessionWriteException`（会在 `_prunePins` 处需额外捕获，否则破坏 `saveNotebook`/`_afterAssignmentsChanged` 主流程）；② 改走 `repository.runScopedWrite`（破坏现有可控仓库子类覆写 `savePinnedAssignments` 的测试接缝）。
- **D2：`_togglePinKey` 与 `reorderPinned` 写后守卫为 `if (!persisted || !stillOwned()) return;`**
  - 决策：写前保持既有 `canToggle()` / `_pinnableKeys()` 校验；写后仅校验 `persisted` 与会话归属（`generation == _generation && account == _account && _authenticated && !_disposed`），不重查 `canToggle()` 或 `_pinnableKeys()`。
  - 理由：跨分钟边界（如考试在 `savePinnedAssignments` 期间到期）下已提交磁盘的置顶/重排必须同步到内存，保持 `640916d` 的跨分钟修复；同时继续拦截写期间发生的登出、切号或销毁。
  - 被否方案：写后重查 `canToggle()`（会导致磁盘已写、内存未更的分裂态，破坏 `an exam ending during pin save keeps stored and active pins in sync`）。
- **D3：`_prunePins` 保持先更内存 `_pinned = retained; _pinsNeedSave = true;`，仅当 `persisted && 仍属当前会话` 时清零 `_pinsNeedSave`**
  - 决策：`_prunePins` 仅在 `persisted && generation == _generation && account == _account && _authenticated && !_disposed` 成立时置 `_pinsNeedSave = false`；遇 `StaleSessionWriteException`（`persisted == false`）或普通异常（`catch (_)`）均保留 `_pinsNeedSave = true` 且不抛出异常。
  - 理由：`_prunePins` 触发时对应课业/手记已完成、隐藏、删除或考试结束，内存不得回滚保留悬挂置顶；保留 `_pinsNeedSave = true` 让后续 `_afterAssignmentsChanged(updateAssignmentReminders: true)` 或 `saveNotebook()` 自动重试补写；若期间已登出/切号，目标入口（`logout`/`_restoreAccountData`/`loginChaoxing`）已递增 `_generation` 并重置新会话的 `_pinsNeedSave = false`，不存在跨账号污染。
  - 被否方案：拒写时回滚 `_prunePins` 内存 `_pinned`（会使已完成/已删除项在首页仍显示置顶，违背 `assignment_store.dart:1530-1531` 重试语义）。
- **D4：`saveNotebook` 补齐 `_pinsNeedSave ||` 重试入口与 `_prunePins` 后会话守卫；其余调用方无需修改**
  - 决策：`saveNotebook` line 240 改为 `if (_pinsNeedSave || _pinned.keys.any(ManualEntry.isManualKey)) { await _prunePins(); }`，其后立即校验 `if (_generation != expectedEpoch || !_authenticated || account != _account || _disposed) return;` 再进入 `_afterAssignmentsChanged(updateManual: true)` 与 `_recordManualCancellationOutcomes`。
  - 理由：`_afterAssignmentsChanged`（line 4000–4006）及其 13 处 `updateAssignmentReminders: true` 调用方（`_reloadJournal`、`_mutateCourseworkState`、`_mutateCourseTermPreferences`、`followCourse`、`setNotificationDetails`、`saveReminderRule`、`saveAllowUrgentDeadlineNightBreakthrough`、`saveDeadlineChannelId`、`createTodoFromNotice`、`createTodoFromChapterNode`、`retryReminderRecovery`，以及登出/登录回滚空操作路径）均在 `await _prunePins()` 后已有 `if (!_isSessionCurrent(snap)) return false;` 保护，无需修改；唯独 `saveNotebook` 走 `updateAssignmentReminders: false` 并直接调 `_prunePins()`，须补齐上述两处。
  - 被否方案：仅改 `_prunePins` 不改 `saveNotebook`（纯手动待办场景下最后一个手动置顶落盘失败后无法经后续手记编辑自动重试）。
- **D5：隔离 MuMu `androidTest` 采用独立 ASCII 镜像预构建 + `scripts/run_android_tests.py --serial 127.0.0.1:16384 --work-dir <dir> --skip-build`**
  - 决策：不修改共享工作树中的 `android/local.properties`（被 `.gitignore` 忽略，当前指向缺少 `android-36`/`ndk 28.2.13676358` 的 `C:\rea-tools\android`）与 `scripts/run_android_tests.py`；在独立纯 ASCII 目录 `D:\campus-tools\build-work\androidtest-1828-<timestamp>\local_app` 镜像源码并写入 `sdk.dir=D:\\campus-tools\\android` 与 `flutter.sdk=D:\\campus-tools\\flutter`，使用 JDK 17（`D:\campus-tools\jdk17.0.21_0`）构建 Debug APK 与 AndroidTest APK，再交由 `scripts/run_android_tests.py --serial 127.0.0.1:16384 --work-dir <dir> --skip-build` 实跑 3 批 112 项并留存日志。
  - 理由：AGP 读取 `local.properties` 优先于 `ANDROID_HOME`；该方案完整验证 `run_android_tests.py` 的清单守卫、保护设备拒绝、批次间卸装重装、全限定类名 `am instrument` 与结果汇总解析，同时严守 `ROADMAP.md` 不擅改工程脚本的门禁。
  - 被否方案：① 直接不带 `--skip-build` 运行 `run_android_tests.py`（复制无效 `local.properties` 导致 Gradle 找不到 `android-36`/NDK）；② 修改 `scripts/run_android_tests.py` 或工作树 `local.properties`（超出本阶段授权范围）。
- **D6：阶段自测包 `1.8.28+122` 后置至 Gate 通过后决定，Stage 1 保持 `1.8.27+121`**

## 9. Gate 审查要点

- **审查 Diff 区间**：`<本方案落盘提交>..HEAD`（增量审查本轮全部 commit，含测试期间任何临场修复 commit）。
- **高风险耦合面**：
  1. `_savePins` 返回值契约：`LocalStorageLeaseReleaseException` 是否仍返回 `true` 且在会话仍有效时写 `_recoveryWarnings`；`StaleSessionWriteException` 是否返回 `false` 且不设 `_error` / `_recoveryWarnings`；其他存储异常是否照常抛出。
  2. `_togglePinKey` 与 `reorderPinned`：写后是否严格执行 `if (!persisted || !stillOwned()) return;`（未误加回 `canToggle()` / `_pinnableKeys()` 重检，也未漏掉 `_pinsNeedSave = false` 的门控）。
  3. `_prunePins` 与 `saveNotebook`：`_prunePins` 是否仅在 `persisted && 仍属当前会话` 时清零 `_pinsNeedSave`；`saveNotebook` 是否补齐 `_pinsNeedSave ||` 与 `_prunePins` 后置会话守卫，且不中断已落盘的 `saved = true`。
  4. `assignment_store.dart` 净增是否 `<= 20` 行，是否存在未授权改动（如 `run_android_tests.py`、Kotlin 用例、UI 文件、版本号文件）。
- **临场修复核查**：逐一检查是否有临场修复 commit 削弱/删改既有断言、用实时 `DateTime.now()` 规避跨分钟边界，或漏改 `_togglePinKey` / `reorderPinned` / `_prunePins` 三处联动之一。
- **自动化未覆盖须人工/日志核查点**：
  1. 核对 `<workDir>\androidtest-3batches.log` 原始文本中的 3 批用例数（20 / 80 / 12）、`unknownTimeNewAssignmentPublishesSilentlyOnSilentChannel` 的 `STATUS_CODE: 0`、以及所有 `STATUS_CODE: -4` 跳过项确实仅限合法假设跳过；
