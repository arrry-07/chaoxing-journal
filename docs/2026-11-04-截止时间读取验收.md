# 截止时间读取修复验收（1.2.4 / 34）

依据[先行方案](plans/2026-11-04-截止时间读取修复方案.md)执行，保留上一轮首页与统计改版。旧验收中的“11份无截止”是当时的错误表现，本记录以本轮真实请求为准。

## 根因与证据

1. 新版正式作业接口 `work/api/task` 的 `endTime=0` 被32–33版解释为可信的“未设置截止时间”，并直接返回；没有继续访问该作业的 `taskUrl`。因此不是展示格式问题，也不是模拟器没装官方App导致的故障。
2. 本轮通过本应用独立登录会话和HTTP请求，在MuMu读取40门课程、31份正式作业（20份完成、11份待交）。11份待交的列表截止字段为0；详情读取均返回HTTP200。
3. 10份详情提供“作答时间：月日 时分 至 月日 时分”，没有年份。列表提供同一作业的完整 `startTime` 毫秒时间戳。转换北京时间后，与详情的开始月日时分相符，才用该年份及跨年顺序消歧结束时间。未使用当前年份、课程学期或上传时间猜测。
4. 剩余1份详情是1172字符的“未开始”页，提供“开始时间：2026-11-05 08:00”，没有截止时间。保留记录，显示“尚未开放，截止时间待确认”，不把开始时间当截止。
5. 固定参考 `fetch_homework` / `fetch_homework_detail` 证实应复用列表条目的独立签名详情URL；参考中的日期推年和空提交状态宽松策略没有照搬。未恢复活动、课堂题或考试fallback。

## 修复行为

- 旧HTML与新版正式作业列表共用详情补读。未完成且没有可信截止时间才补读；已完成或已有可靠绝对截止时间不多请求。
- 区分精确时间、明确不限、仅月日年份待确认、尚未开放和读取失败。解析时去掉脚本与样式，只有明确不限才清除旧日期。
- 网络、拒绝访问、验证码等保留作业行；截止补读失败时仓库保留旧可信日期。验证码或详情认证失效停止后续详情及课程请求，保留本轮成功列表；剩余未读课程另记列表阶段问题。诊断保留错误类别、HTTP状态和详情阶段。
- 旧缓存中“空日期＋raw=0”的错误可信标记降级，不清空数据。首页仅截止补读不完整时显示“部分截止时间待确认”，不声称课程列表未更新或显示上次记录。
- 日历与提醒仅使用可信绝对时间；年份待确认的原始月日仍可查看。小组件使用相同截止状态。最终诊断仅记录状态码、字符数和证据布尔值，不记录凭据、完整响应或签名URL。
