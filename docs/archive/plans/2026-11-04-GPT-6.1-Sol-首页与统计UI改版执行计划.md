### 3.1 保留与收敛

- 首页去掉 `CAMPUS JOURNAL / 01` 装饰眉题，品牌名保持“学习通课业手记”。不改桌面名称、包名或品牌定位。
- 视觉方向为“暖纸上的作业清单”：统一宽度、清晰分组、轻分隔。每张条目保留一层轻纸面即可，取消重复细框、阴影和内外套框。

这是合成布局示例，数字不是对用户当前数据的断言。

- 移除“下一份要交”和“近期待交”两段对同类数据的拆分。最早到期的作业成为“近期截止”的首条，通过紧急度文字强调，不额外套一张大卡。

- 只有需要确认作业：主内容直接显示“有 N 份作业需要确认”，默认展开该组。
- 有近期作业时，其他组可折叠，但数量始终可见；展开状态不能每次 store 通知后重置。
- 从详情返回保留滚动位置和分组展开状态。

### 3.4 作业条目信息顺序

1. 作业标题与简短紧急度，例如“今天截止”“已逾期2天”。窄屏或大字体时紧急度另起一行，不挤压标题成窄列。
2. 课程名称。不显示班级编号、不拼接来源或技术信息。
3. 可信的绝对截止时间，必要时附提交状态。相对时间不能代替绝对时间。
4. 无截止、读取失败、历史时间不可信必须各用对应文案，不能统一写“未设置”。长诊断在详情。

颜色：正常待提交用墨色；今天截止或逾期才使用更明显的强调；待确认使用温和提示色并保留文字。已提交、待批阅不出现“待交”标记。

不得用正则删除全部数字或“班”字。`大学物理B（下）`、`高等数学2`、`2026专题`都是合法课程名。若原始 courseName 确有明确附带的元数据，先举证再做局部展示格式化，默认只移除当前卡片的 clazzId 拼接。

## 4. 首页状态与数据规则

### 4.1 同步展示状态表

同步区域常态一行，必要时两行；详情入口与主要动作分开，不出现斜杠复合按钮。正常成功用更新时间，不保留大段成功公告。

| 状态 | 摘要 | 动作 | 内容处理 |
|---|---|---|---|
| 首次未同步，无记录 | 尚未读取作业 | 读取作业 | 引导空态，不宣称暂无作业 |
| 同步中，无缓存 | 正在读取作业… | 不允许再次同步 | 稳定的加载占位；不显示成功空态 |
| 同步中，有缓存 | 正在更新… | 同步详情可用，刷新禁用 | 保留已有条目和位置 |
| 完整成功，有记录 | 刚刚更新 / HH:mm 更新 | 次级同步详情，顶部刷新可用 | 作业为主体 |
| 完整成功，确实无正式作业 | 刚刚更新 | 正常刷新入口 | 暂无作业，可用简洁空态 |
| 完整成功，仅已完成或被筛除 | 已更新 | 查看全部记录 / 管理课程 | 明确为何首页为空，不谎称未抓到 |
| 部分成功 | 部分课程未更新 | 查看详情 | 有记录正常展示；详情给具体失败课程 |
| 全失败，无缓存 | 暂时无法读取作业 | 根据原因重试、登录或验证 | 不显示上次记录，也不显示暂无作业 |
| 全失败，有缓存 | 更新失败，以下为上次记录 | 根据原因选择动作 | 更新时间指向真正成功时间，不用本次尝试时间 |
| 提醒/小组件故障，作业成功 | 作业已更新，提醒需要处理 | 去处理 | 不把数据成功标成全失败 |

操作语义：网络等可重试问题点击“重试”必须发起同步；“同步详情”仅跳详情；认证失效使用重新登录入口；验证码使用现有验证入口。不能新建第二条认证流程。不能因为同步中就显示重试。

检查截图顶部刷新圆环是否是 `RefreshIndicator` 下拉阶段的原生指示，不要仅凭截图认定标题被自定义浮层遮挡。最终应保证自动同步不弹阻挡标题的浮层；用户下拉刷新可保留原生短暂反馈，不另叠第二个圆环。

### 4.2 作业分类

正式来源、关注课程、隐藏记录等现有规则继续生效。每份未完成作业只能进入一个首页组，推荐优先顺序：

1. `!isPendingConfirmed`：需要确认（提交状态待确认）。
2. 已明确待交，但 `deadlineReadFailed` 或已有日期不可信：需要确认（截止待确认）。
3. 已明确待交、无截止且没有读取失败证据：未设置截止时间。
4. 已明确待交、有可信截止：按照过去、未来30天内、30天之后分为逾期、近期、远期。

边界沿用当前精确30天窗口，避免未经授权变成“到月底”。统一一次传入 `now`，不在同次构建多次取时。显示日期继续用既有北京时间规则。完成作业不进入这些组。

`deadlineAt == null` 不能单独证明老师没设置时间；必须检查读取失败、可信度与已有数据来源。当前模型无法证明时用“截止待确认”，不能猜测。

不要为了新界面直接删除 `HomeAssignmentGroups.uncertain` 等公共行为；先检查引用与测试。如果拆分字段，逐个更新调用者并保留原始数据不变。

## 5. 扇形图与统计语义

### 5.1 唯一统计范围

默认使用现有 `store.formalAssignments`：本机已读取、当前关注课程的正式作业；保持隐藏记录的既有排除行为。页面用简短说明“当前关注课程 · 本机已读取记录”，不暗示只统计本学期或近30天。

三类互斥集合：

```text
completed = isCompleted
pending   = !isCompleted && isPendingConfirmed
unknown   = !isCompleted && !isPendingConfirmed
total     = completed + pending + unknown
```

- 继续遵循现有 `isCompleted`：已提交、待批阅、已批阅、已完成均不需要再次提交。
- 已退回属于待提交，已逾期是待提交的子集；截止未知不等于提交未知。
- 饼图每段角度 = 该类数量 / total × 2π。任何分区不得重复计数。
- 主文案建议“已确认完成 X%”，旁列“已完成 C 份 / 待提交 P 份 / 状态待确认 U 份”。有未知时补一句“待确认记录计入总数”。不把它包装成准确预测的实际完成率。
- 若未知为0，仍保持一致定义；零数量项可保留在图例但不画扇区。
- total=0：显示“暂无可统计的作业”，不画伪0%或空分母饼图。
- 全部状态未知：画单个中性扇区并突出“全部状态待确认”，不以醒目“0%已完成”断言用户什么都没交。
- 全部完成或全部待提交：实心单色圆，旁边文字准确呈现100%，不要画退化细线。
- 百分比四舍五入仅影响文字，不影响角度；如图例要求合计100%，用统一的最大余数分配，避免独立取整产生99%或101%。
