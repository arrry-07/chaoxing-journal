# 截止时间读取修复方案

用户已要求先输出方案再按方案实施。本方案在产品代码修改前形成，沿用既有UI、身份和独立会话链路。

## 已确认事实

- 新版正式作业路径只读work/api/task，将endTime=0当可信无截止，没有访问taskUrl详情。这不足以证明老师未设置时间。
- 固定参考fetch_homework_detail复用列表返回的独立详情URL，截止通常在详情中。空状态pending的参考宽松策略不覆盖Android未知状态保护。
- 当前HTML解析只支持少数时间段格式；无年份不猜年份。现有仓库在deadlineReadFailed时会保留旧日期，可继续使用。

## 实施顺序

1. 先加失败回归：列表零值、缺字段但详情有日期；明确无期限；详情网络/权限/风控；缺年份；无效日期；跨年；旧缓存0值。
2. 为旧HTML与新版JSON共用详情补读函数。未完成且列表没有可靠正数截止时间时，复用原taskUrl，按可信域规则跟随跳转。已完成不额外请求，列表已有可靠绝对毫秒时间时不增加无意义请求。
3. 日期解析返回结构化证据：精确截止、明确不限、仅月日待确认、无法识别。支持实际响应中已证实的标签、起止区间和必要隐藏字段；忽略脚本/说明中的伪标签。相对剩余时间、发布时间不作为精确截止。缺年份只能用同一份响应中明确的年份/时间戳消歧，不用今天猜年。
4. 详情失败保留作业行及缓存可信日期，诊断保留具体阶段/错误类别。风控停止进一步详情与剩余课程请求，已有列表与成功结果保留，不恢复活动/考试兜底。
5. 仅详情明确无期限才可清除旧截止。旧版本raw=0且日期为空的可信无截止标记降级为待确认，不删数据。无法确认时首页、详情、小组件显示待确认或读取失败，不能写未设置。
6. 在MuMu做一次受控真实同步，记录状态码、请求阶段、日期格式/解析结果和总数；不记录账号、密码、Cookie、整页响应或完整签名URL。需要人工验证时交由用户处理。
7. 核对首页/详情/日历、提醒与小组件消费者，跑适用单测、全套、静态分析、参考CLI核心测试、Android构建；输出可覆盖测试APK、真实或样例截图、未完成证据边界。
8. 自动Git提交和推送现有私有仓库分支，更新PR说明。不上传APK、不公开仓库、不改正式签名。

## 验收标准

有截止的真实详情可以得到相同绝对日期或诚实显示原始月日待确认；确实不限有明确详情证据；失败不丢记录/旧可信日期；未知年份不造日期；没有凭据或签名链接泄露；测试、构建和实机证据分别报告。
