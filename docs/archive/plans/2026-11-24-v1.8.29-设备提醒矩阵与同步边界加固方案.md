### 架构与实现决策（执行 AI 不得重新取舍）

- **D1：新增 `_ownsAuthenticatedSession(int generation, String? account)` 仅收敛目标 5 处（6 个表达式），绝不复用 `_isSessionCurrent`**
  - 决策：在 `assignment_store.dart` `_savePins` 紧上方新增：
    ```dart
    bool _ownsAuthenticatedSession(int generation, String? account) =>
        !_disposed &&
        _authenticated &&
        account != null &&
        generation == _generation &&
        account == _account;
    ```
    仅替换 `saveNotebook:243-246`、`_togglePinKey:1409-1413`、`reorderPinned:1447-1451`（保留 `!_manageBackgroundSchedule`）、`reorderPinned:1457-1460`、`_savePins:1479-1482`、`_prunePins:1542-1546`。
  - 理由：零行为变更、净减 `assignment_store.dart` 约 14–18 行、避免影响 `_syncCancelled` 与未登录路径，且不波及 20+ 处既有方法。
  - 被否方案：① 复用 `_isSessionCurrent(_SessionSnapshot)`（会错误放行未登录态或受 `_syncCancelled` 干扰）；② 全文件批量替换 25+ 处（含 3 条件旧分支，改变未知边界且 Diff 过大）。
- **D2：API 33+ 通知拒权与 API 34+ 精确闹钟默认拒绝必须用独立新批次 `batch4_api_matrix_and_doze` 的「全新安装自然拒绝态」验证，严禁在进程内 `pm revoke` 或 `appops deny`**
  - 决策：利用 `run_android_tests.py` 批次间 `uninstall` + `install -r`（不带 `-g`）的全新安装特性，在 `ReminderApiMatrixTest` 中用 `@FixMethodOrder(MethodSorters.NAME_ASCENDING)` 按序执行：`a`（自然无 `POST_NOTIFICATIONS` → 阻塞记录 `notificationPermissionOff` + DB 保持 `STATUS_PENDING`）→ `b`（`grantRuntimePermission` 授权不杀进程 → 投递成功）→ `c`（API 34+ 自然无 `SCHEDULE_EXACT_ALARM` → `scheduleDeadline` 降级 `setAndAllowWhileIdle` 不抛异常且 `hasDeadlineAlarm == true`）→ `d`（`appops set <pkg> SCHEDULE_EXACT_ALARM allow` 升权不杀进程 → `ReminderSystemReceiver` 对账重建闹钟与 WorkManager 约束）。
  - 理由：Android 13+/14+ 对运行中进程执行 `pm revoke` 或将 `SCHEDULE_EXACT_ALARM` 从 `allow` 改为 `deny` 会由系统立即杀进程，导致 `AndroidJUnitRunner` 报 `Process crashed`。采用「自然初始拒绝 → 仅单向升权」既真实还原用户首次安装态，又 100% 稳定不杀进程。
  - 被否方案：① 在 `@Before`/`@Test` 内执行 `pm revoke` / `appops deny`（必触发系统杀进程致测试崩溃）；② 改为 `adb install -g`（掩盖 API 33+ 首次拒权与 `ReminderAggregateNotificationTest` 缺授权缺陷）。
- **D3：Doze 演练由宿主侧 `scripts/run_android_tests.py --doze-probe` 托管并带 `try...finally` 强制复位**
  - 决策：在隔离设备上，宿主脚本先读 `dumpsys deviceidle get deep` 基线，再执行 `dumpsys battery unplug` → `dumpsys deviceidle force-idle` → 跑 `ReminderApiMatrixTest`（或单独 Doze 用例）→ 读取 `dumpsys alarm` 校验目标包闹钟已登记，无论成功失败都在 `finally` 中无条件执行 `dumpsys deviceidle unforce` 与 `dumpsys battery reset`。
  - 理由：避免仪器测试异常中止后把模拟器永久遗留在 Deep Doze / 拔电状态污染后续测试。
  - 被否方案：仅在 Kotlin 用例内调用 `dumpsys deviceidle force-idle`（进程崩溃时 `finally` 无法执行）。
- **D4：`scripts/run_android_tests.py` 实行“三层硬拦截 + 读写双模式”**
  - 决策：① `PROTECTED_SERIALS = {"127.0.0.1:16448"}` 与 `PROTECTED_FIRST_INSTALL_TIMES = {"2026-11-04 19:05:10"}` 永远不可绕过（退出码 `2`）；② 破坏性仪器测试默认只允许模拟器/可重装虚拟设备（`ro.kernel.qemu == "1"` 或 `ro.build.characteristics` 含 `emulator` 或 serial 前缀 `emulator-` / `127.0.0.1:`），遇到物理真机或未知设备默认拒绝（除非显式 `--allow-wipe-physical`）；③ 新增 `--oem-readonly-audit` 纯只读体检模式，严格白名单只执行 `getprop`/`dumpsys`/`appops get`，绝不执行 `uninstall`/`install`/`pm clear`/`am instrument`；④ 永远禁止向 `am instrument` 传递 `-e realAccount true`。
  - 理由：防止物理 OEM 真机（如日常华为手机）连上 ADB 后被误卸载清空个人数据，同时守住 0 线上请求与 0 `9010` 风险。
  - 被否方案：沿用单 `PROTECTED_SERIALS` 集合（无法防护 USB 真机或换端口的保数据 MuMu 实例）。
- **D5：隔离镜像自动修补副本 `android/local.properties`，绝不修改共享工作树**
  - 决策：`_build_root()` 在复制到 ASCII `work_dir/local_app` 后，检查 `--sdk-dir` 参数、环境变量 `ANDROID_SDK_ROOT` / `ANDROID_HOME` 及常见本机路径（优先保留副本内已有且含 `platforms/android-36` 的路径；若指向缺失 `android-36` 的旧路径则仅覆写**副本**的 `android/local.properties`）。
  - 理由：消除每次跑 `androidTest` 都要手工 `robocopy` + `Set-Content local.properties` 的易错手工步骤，同时保持工作树 `local.properties` 零改动。
  - 被否方案：要求修改仓库工作树内的 `android/local.properties`（影响本地其他配置且与开发指南违背）。
- **D6：方向 2 坚持「离线合成全量跑绿，线上最多按需 1 次集中刷新，自然 9010 绝不人为诱发」**
  - 决策：M2 在 `test/sync_and_exam_boundary_190_test.dart` 用离线夹具跑绿四类边界；Stage 1 不发任何学习通线上请求。真实样本缺口留到后续维护者按需 1 次刷新或自然触发时对照下方「无法离线区分的根因与最小判别检查」核对。
  - 理由：遵守 `VALIDATION.md:9` 与 `AGENTS.md:23` 防高频刷接口触发 `9010` 约束。
  - 被否方案：在 Stage 1 内对保护实例 `127.0.0.1:16448` 反复刷新学习通线上接口。
