## 产品约束与交互规格

### A. 正式作业与旧数据

默认产品仅展示课程班级“作业”页的正式作业。课堂抢答、随堂练习、活动、竞赛题目和考试不作为正式作业备用源。本轮选择移出默认集合，不扩展课堂题目入口；旧数据保留在本地记录的“历史与其他来源”中，便于核对和恢复。

新增来源字段（建议 enum AssignmentSource: courseWork / classroomActivity / exam / manual / legacyUnknown）。正式来源必须有 courseId、clazzId、workId 的稳定身份；课程引用单独持久化，courseId+clazzId 为键。旧 cx:work ID 可迁移为 courseWork，cx:activity 与 cx:exam 分类保留；其他记录默认 legacyUnknown，仅在可验证的正式作业链接或后续正式响应匹配时升级，不能全部冒认为正式作业。

签名作业页失败时返回该课失败信息并保留旧正式记录，禁止用活动填补“成功”。不需要活动的业务取消对应请求，其失败也不影响正式作业完整同步时间。当前学期无法可靠从响应识别时，允许用户管理“首页关注课程”，默认所有已识别正式课程参与，不能凭作业日期猜课程学期。

日期以详情“截止/作答结束”而非发布时间、开始时间为准。显式年份和时间戳按原值保存；北京时间墙上时间转换为统一 instant。缺年份结合起止区间及服务端上下文解析，证据不足标为截止待确认，保留原文，不能用今天最近年份静默猜测。首次来源不确定的数据不进默认日历；旧已确认时间读取失败可保留，但明确标“上次读取”。

首页数据分组（时间窗为可执行的产品默认值，不是现有实现）：

- “近期待交”：可信截止在 now 至 now+30天，未提交、退回；按截止升序，今天截止优先视觉提示。
- “更远期待交”：大于 now+30天，折叠并提供查看；不丢数据。
- “截止待确认”：正式来源但截止未知、过期旧日期且状态未知的记录分组核对，避免伪装为确认未交。
- “已逾期”：已确认待提交且可信截止小于 now，默认折叠，最近逾期排前；3月历史不再置顶。
- 提交状态未知不放“下一份要交”强结论位；未来截止且未知的记录纳入待确认入口并提示数量，避免悄悄漏掉。
- 已提交/批阅退出待交；退回重做重入；用户隐藏退出默认集合，可恢复。分类/关注/隐藏规则同步影响日历、提醒、小组件和统计，但历史仍可查。

### B. 登录与同步状态

认证与非必要资料加载、全量作业抓取分开。完成必要认证会话且凭据保存成功后进入首页；头像、昵称与首次同步后台进行。不可只提前改按钮文字，实际仍 await 全课程。自动同步与首次同步合并为同一 in-flight；退出/切号用 generation 或 CancelToken 忽略旧结果。

记录 request stage、elapsed、HTTP status、错误分类、课程计数，不记录 Cookie、密码、账号或带 enc 的完整 URL。证据区分 network / authExpired / verificationRequired / forbidden / schemaChanged / partial / storage / notification / widget；普通连接可用并不能证明学习通认证接口可用。

首页仅一条摘要：首次同步中“正在读取作业…”；部分成功“已更新 N 门课程，M 门待重试 · 查看”；完全失败“本次未能读取作业 · 重试 / 查看原因”。有旧数据时显示“显示上次记录”。不把逐课课程名堆进首页；同步详情内可展开按课程列表。

时间分别记录最后尝试、最后有数据成功、最后完整成功；全失败不推进成功时间，部分成功允许更新时间但不能冒充全量完整成功。无首次成功不能写“暂无作业”，应写“尚未获取作业”。冷却继续保留，不因切前台连发全量请求。

性能验收：在认证/安全存储立即成功、资料和同步人为阻塞的测试中，认证完成后 500ms 内可进入首页（测试目标，不是公网耗时承诺）；正常网络实机记录分段耗时，多课程同步不能阻塞导航。离线/风控场景显示明确反馈，不能承诺任何网络都秒登。

### C. 个人页

- 关于：主内容为名称、维护者、版本和用途；“开源许可”独立入口保留第三方版权。仓库来源文档保持真实。
- GitHub 源码：点击行主体复制完整 HTTPS 地址，轻提示“链接已复制”；右侧独立“打开链接” IconButton 在浏览器打开，带 tooltip、Semantics。打开按钮不触发行复制；不再用无回调 Icon 假装按钮，也不冒用系统分享图标。
- 帮助与反馈：进入内部公告/帮助页。离线可见更新说明、同步/权限/隐藏/更新 FAQ、已知限制、反馈模板、复制反馈信息按钮。“前往反馈”是页内用户主动动作；私有 Issues 需要权限时明确说明，提供复制模板，不捏造邮箱、QQ群或不存在的提交成功。
- 本地记录：增加实际页面入口及右侧 >。页内提供正式/历史与其他来源/已隐藏分类、搜索、最后读取时间与来源，支持逐条查看和恢复；本轮不做破坏性一键清空。
- 我的课程：正式课程引用按班级稳定键生成，采用单列课程行而非 Wrap；课程标题最多两行、次行班级和待交数，同名多班不能按课程名合并。最多展示4条，再“查看全部”。课程管理提供关注/不关注；竞赛若确为服务端课程仍保留在全部课程，不靠名字黑名单。

### D. 作业卡片与日历

作业卡片统一浅纸面、1px 分界边框、12px 圆角、12–16px 内边距，卡片间12px。内容依次为作业标题、课程/班级、截止时间、一个主状态与可选时间提示；状态标签在同一 Wrap 行布局，允许大字体自然换行。未知状态用“提交状态待确认”，已确认待交且过期才用“已逾期”；未知且过去用“截止已过 · 提交待确认”，不制造两个互相竞争的强状态。详情/隐藏动作语义清楚，共用 AssignmentCard 避免首页与日历样式分叉。

日历默认选今天；日期格显示今天轮廓、选中填充、截止事件数量/圆点。普通待交用墨绿，逾期用莓红，待确认用琥珀并配图例及文字语义；同日多条显示数量，不能只靠4px点。下方默认只列所选日议程，“本月”切换才列当前月；切月清除旧月选择并自动选新月1日，回到今天按钮恢复今日。选中无事件要说“当天暂无截止作业”，读取失败与真无数据不能混同；无截止记录只显示数量入口，不随便分配某一天。午夜到时、跨月/跨年、状态提交或隐藏后标记与议程同步更新。

### E. 更新与覆盖安装

目标流程：点击检查 → App 内检查进度 → 无更新/失败/需认证各自明确 → 有更新显示版本、更新说明、大小 → 用户选“下载并安装” → 流式下载进度、可取消/重试 → 完整性与安装身份校验 → 系统安装确认 → 返回后核验已安装版本。无需用户先去 GitHub 才能得知有无更新；浏览器只作为明确的备用操作。

默认建议方案：源码仓库继续私有，使用独立公开分发仓库（只含 APK 与版本清单）或公开 HTTPS 分发端点。实施时先完成清单解析、模拟检查/下载/安装测试；实际创建公开渠道和上传前需用户确认，因为这会公开 APK。若 APK 也必须私有，再选择用户授权访问或受认证分发服务，另行确认基础设施范围；没有公开渠道或认证就不能承诺匿名一键读取私有资产。

版本清单字段固定为 schemaVersion、applicationId、channel、versionName、versionCode、minSdk、supportedAbis、apkUrl、apkSize、sha256、signingCertificateSha256、releaseNotes、publishedAt。以 versionCode 判断可升级，versionName 仅展示；版本相同不重复提示。来源 URL 必须 HTTPS、校验重定向；下载大小上限和内容长度校验，失败清理半成品，哈希一致后再安装。先验证 APK 实际包名/证书/版本与当前安装身份匹配，不只信清单里的文字。

当前体验包 .journal 与默认 release 包名不同，不可直接用默认 release 冒称覆盖包。实施前从旧 APK 提取真实 applicationId、versionCode、证书指纹，使用原兼容身份和原签名链出覆盖包；密钥不可用则明确阻塞，不改包名规避。普通 Android App 必须经系统安装确认，不能承诺静默安装；不卸载旧包。验收后账号、记录、隐藏与提醒规则仍保留。

依据：[GitHub Release API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)、[GitHub 资产 API](https://docs.github.com/en/rest/releases/assets#get-a-release-asset) 说明公共资源可匿名访问，私有资产需要合适授权；[Android App Signing](https://developer.android.com/studio/publish/app-signing) 说明签名和升级身份约束。本文为产品方案，没有更改仓库可见性或发布文件。
