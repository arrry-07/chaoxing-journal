## 7. 推荐执行顺序

### Phase 0：基线与问题冻结

1. 新会话先读取 `AGENTS.md`、`PROJECT_STATE.md`、`docs/ROADMAP.md`、`docs/待处理体验反馈.md`、本交接和 1.8.16 发布记录。
2. 执行 `git status -sb`、`git log -n 5 --oneline`、`git tag --points-at`，并核对 GitHub Release、latest、Gitee 两份 JSON 和官网静态版本；不要把本文的哈希当作新的验证结果。
3. 确认远端 `v1.8.16` 与 Release 未动；新工作分支从最新 `origin/main` 建立。如果仍在本交接工作树执行，先确认其 `main` 已更新。
4. 把问题台账转为具体任务，逐项写“复现/证据 → 根因 → 测试 → 修复 → 设备 → 发布”，不接受只按文档打勾。

### Phase 1：立即可做的测试与数据安全闭环

1. 完成 R-01 的状态矩阵回归；如果生产逻辑与既有语义不一致，先写出失败测试再修。
2. 完成 R-11 的备份恢复演练，使用隔离 AVD，不触碰受保护 MuMu 数据。
3. 复现 R-04：如果 1.8.16 当前仍出现同步问题，保存脱敏诊断，按 `stage + kind + message` 聚合后的真实组数判断；如果未出现，记录时间与环境，不为“旧 29 条”虚构代码修复。
4. 这批若没有用户可观察的生产代码变化，只保留测试/验证结果，不创建无效新版本；若确有小范围可复现缺陷，再冻结下一补丁（先检查 `1.8.17+84` 是否空闲）。

### Phase 2：真实样本与来源接入

1. 按第 6 节收集 S-02/S-03；只有同时得到正式任务正例、合法只读范围、稳定身份、个人状态和截止信息，才为 `groupHistory` 设计数据模型、去重和失败保留。
2. 在此之前保持同步页 `尚未启用`，不得把群消息正文、签到卡或普通聊天当成正式作业，不得发送群消息、修改群或绕过权限。
3. S-04 到达后先做两个不同课程作业的入口/身份对照，再决定 Android Intent/URL Scheme 或安全 fallback；保留网页入口作为失败兜底。
4. S-05/S-01 只用于验证既有分支；如果没有发现代码差异，结论应为“真实样本通过/仍缺”，不是“状态矩阵全量通过”。

### Phase 3：设备与系统矩阵

1. 先用当前可用 API 26/30/35 镜像补齐安装、后台、通知、闹钟和升级路径的已有缺口；API 31/33/34 通过 `sdkmanager` 取得镜像后建立隔离 AVD。
2. 华为 API 29 先以原签名保数据升级到 1.8.16，再验证 R-07 和 R-10；普通 MuMu 不作为实体 Launcher 证据。
3. TalkBack 需要实际可用的无障碍服务；屏幕朗读关闭、未安装 TalkBack 或没有人工听读时，只能记“未验证”。
4. 自然官方通知 R-08 只能等待真实到达，不能用测试通知或合成 signal 代替。
5. 所有设备测试记录机型、API、安装时间、版本、数据计数、APK 哈希和失败边界；破坏性测试放隔离环境。

### Phase 4：签名迁移

1. R-12 属于比普通补丁更高风险的发布工程，不是“换一个 keystore”即可完成。未经用户明确批准，不生成新密钥、不改变证书。
2. 批准后的首选路径：旧证书桥接版放宽 `MainActivity.inspectApk()` 的谱系判断 → 离线新密钥与 v3.1 lineage → `rotation-min-sdk 33` 轮换候选 → API 26/27/29/31/32/33+ 矩阵 → 旧证书继续服务低版本或另行决定退役。
3. 任何卸载重装路径必须先完成备份导出、恢复演练和用户数据确认；不得把 Auto Backup 当成登录态/提醒恢复。

### Phase 5：产品功能缺口

1. R-13 教务考试、R-14 官方授权登录分别建立研究规格，不从猜测接口直接实现；它们不是当前学习通正式作业修复的同批补丁。
2. R-15 Gitee 镜像只在维护者选定批量点时处理；索引更新不等于 APK 已镜像。
3. 长期路线图中的深色模式、音效、完整反馈服务、AI、跨设备同步和 iOS 不自动进入本批。

### Phase 6：版本冻结与发布

1. 一个版本只承载一组内聚且已验收的改动；不建议把群历史、签名迁移、设备补丁和长期产品功能混在同一 Tag。
2. 发布前重新核对 Tag/Release 空闲、当前版本元数据、原签名证书、`ANDROID_HOME`、干净 ASCII 导出、Gradle/Flutter/时区/原生检查。
3. 正式包必须有原签名、双 ABI、minSdk/targetSdk、ZIP CRC、16 KiB 对齐和回下载哈希；MuMu 只做保数据覆盖，不卸载。
4. GitHub Release 必发；Gitee `index` 回读成功才算索引完成，APK 镜像是否上传按维护者选择的批量点决定；官网回退按独立 PR/Pages 部署。
5. 没有用户可观察缺陷变化时，只更新测试/状态文档，不升版本；有代码变化时再冻结下一补丁，版本号按现场远端占用确认。
