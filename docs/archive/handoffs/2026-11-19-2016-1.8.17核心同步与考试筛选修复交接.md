## 未闭环的问题与尝试结果

1. **“40 门已更新、1 门待重试”的原因已定位到截止详情。** 相关课程的正式作业列表读取成功，同一轮有 1 条“作业详情未提供可识别的截止信息”（HTTP 200）及 1 条“部分截止时间尚未确认”。同步计数按课程合并截止详情失败，考试来源的错误独立统计。报告只关联到课程，无法唯一定位到哪条课业。现有提示也无法区分正文没有时间、现有解析未涵盖正文结构，或返回了另一种页面。
2. **课程考试跳转仍缺入口证据。** 华为分别刷新三次，诊断观察到 22、23、29 次请求在跟随跳转前被路径白名单拒绝。HTTPS、443、允许的子域均通过。最后一轮 29 条均是 `mooc2-ans-vue/_/stu`，未知段从未原样记录。历史实测出现过 `/mooc2-ans-vue/fanyav3/stu`，当时只见前端外壳，缺少旧版作业凭证。当前还缺新一轮跳转的精确路由类型、发起阶段、课程班级匹配及考试只读凭证证据。三轮诊断包只在本机使用，手机已由普通候选包覆盖。
3. **验证页后来可打开，部分考试来源仍要求验证。** 此前用户收到“验证页面未能打开，请稍后重试”。刷新后应用成功显示验证码，用户完成验证并继续同步，之后仍报告 1 条课程考试来源人工验证。旧报告缺地址是已复现并修复的一条独立失败路径。原始打开失败的具体原因仍不明。源码中的 `_courseVerificationProbe` 在读取各课程时会被覆盖，可能给后续来源选到另一门课的入口。需要再复现并绑定触发来源，本轮仅修复入口提示和展示条件。
4. **旧 CI 失败已处理。** 早期候选 README 缺少元数据检查要求的 `1.8.17（84）` 版本标记，修文档后已通过业务提交的两条 CI。Windows 构建曾报告跨盘 Kotlin 增量缓存错误，编译自动回退后成功。ASCII 干净导出在 Windows 用 Python `tarfile` 解包，避免历史命令的中文路径问题。
