# 启动更新、下载与学习通跳转实施计划

**目标：** 冷启动检测更新并允许忽略当前版本，改善更新下载吞吐，核实学习通作业直达和 MuMu 登录无响应。

**范围与默认选择：** 用户要求优化后直接执行，沿用 Flutter、Dio、SharedPreferences 和现有原生通道。每次冷启动检查一次；后台检查失败不打断；普通关闭仅影响本次，忽略仅影响该远端版本，手动检查仍可用。后台返回不重复弹窗，不在系统登录/验证界面抢焦点。

**方案：** 保留 GitHub 官方渠道和完整 SHA-256、包名、签名检查。大且有可信大小及哈希的 APK 尝试最多4路 HTTP Range；首次服务器返回200则复用该响应单路下载。不添加未经维护的第三方代理。流写入合并为256 KiB批次，保留取消、长度和总时限约束。界面提供实际速度与下载量，不承诺5G线速。

**学习通边界：** 先查本地参考实现、官方资料、已安装客户端的公开 Intent。仅实现有证据的跳转参数；启动客户端不算作业详情验证成功。未登录导致无法核实的路径要明确记录，网页入口继续保留。登录由用户操作，不迁移凭证，不绕过风控或清除用户数据。

## 任务
- [x] 启动检查、当前版本忽略持久化和手动检查回归；覆盖重复检查、失败、重启及新版本重新提醒。
- [x] 分段及缓冲下载；覆盖206准确范围、200回退、错误范围/长度、取消、哈希失败与部分文件清理。
- [x] 核实官方客户端入口并检查 MuMu 网络及用户重试日志；可验证才接入详情按钮，不能验证则交付调查结果。
- [x] Flutter分析/测试、原生检查、构建、MuMu保留数据覆盖验收；更新记录后提交并推送。

## 验收注意
用户5G网络不是当前电脑/MuMu测速网络；受GitHub链路或运营商限制时，多路未必加速。忽略记录写入失败需留在弹窗并提示。网络/取消失败不能发布部分APK。测试数据和设备原始日志不进入Git。

## 实测后的方案调整
同链路四路6.93 MiB/s、单路7.45 MiB/s，默认缓冲单路，四路设为可选。按用户后续参考，首页及详情优先尝试官方包注册的HTTPS handler，不支持自动回退原始网页，不猜私有协议。Android15已覆盖验收，32记录保留。详见本轮验收文档。
