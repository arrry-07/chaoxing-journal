# 更新分发与覆盖安装

当前实现支持匿名HTTPS更新清单，通过编译参数 `--dart-define=UPDATE_MANIFEST_URL=https://<实际域名>/update.json` 配置。默认为空，App显示“更新渠道待配置”，用户可主动选择浏览器Releases备选；不会在APK中放入PAT，也未更改仓库可见性或上传文件。

清单示例（示意值不可直接发布）：

```json
{
  "applicationId": "com.example.studyassistant",
  "versionCode": 32,
  "versionName": "1.2.1",
  "apkUrl": "https://<实际域名>/journal.apk",
  "sha256": "<APK实际SHA256，64位十六进制>",
  "size": 12345678,
  "notes": "版本说明"
}
```

必须提供applicationId、正整数versionCode、非空versionName、HTTPS APK地址和64位SHA256。size可选；没有长度时显示不定进度，仍校验摘要。只按versionCode判断升级，允许同versionName更高versionCode。非200、认证错误与无新版各有不同结果。

下载完成前使用.part文件，取消、长度不符或哈希错误清理半包；摘要通过后原生检查真实包名、当前签名集合、版本增长、最低SDK和设备ABI。当前采取同证书集合的保守策略，不支持自动接受签名轮换。未知来源权限未开时跳设置，弹窗保留已下载路径可重试；打开系统安装器不代表安装成功，不显示“已更新”。

正式覆盖安装需同applicationId、兼容签名和更高versionCode。Android相关依据：[PackageManager](https://developer.android.com/reference/android/content/pm/PackageManager)、[SigningInfo](https://developer.android.com/reference/android/content/pm/SigningInfo)。本次debug为com.example.studyassistant.journal/31，不能作为正式覆盖测试包。

待落实的具体输入：

1. APK是否允许公开分发、实际HTTPS清单与APK地址。清单可以放独立公开资源，无须把源码仓库公开。
2. 如必须私有分发，需要用户可控的授权方案；不把仓库长期令牌硬编码在App。
3. 旧正式安装包的包名、versionCode和证书指纹，以及能继续签名的密钥。不要把密钥或密码提交仓库。
4. 用户授权发布后再构建更高版本、填入真实哈希并上传；先在无真实数据设备验证覆盖后账号、作业、隐藏和关注设置保留。

本次仅本地实现和debug编译；真实APK签名不匹配、权限拒绝、系统取消安装与覆盖后数据保留仍待设备验证。
