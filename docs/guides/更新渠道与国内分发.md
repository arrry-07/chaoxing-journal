# 更新渠道与国内分发

App 内置两条更新检测通道，打包参数决定走哪条：

- **GitHub 通道**（默认）：读 `api.github.com/repos/arrry-07/chaoxing-journal/releases/latest`。APK 下载经 `github.com` 重定向，网络可能间歇超时。1.6.6 的元数据请求保持8秒连接/12秒接收；APK单独使用30秒连接/60秒接收空闲时限、5分钟总上限，正文开始前最多自动重试一次。首个Range探测的唯一重试可回退同源完整请求，仍执行大小和SHA-256校验。旧客户端不会因新版本发布而自动获得这项策略。
- **自定义清单通道**：打包时加 `--dart-define=UPDATE_MANIFEST_URL=<清单地址>` 即启用。App 直接读一个 JSON 清单（含版本号、APK 地址、SHA-256），绕开 GitHub API。清单内容可随时更换，**不用重新发包**。

当前状态：维护者已确认 1.6.3 **暂时只使用默认 GitHub 通道，不启用 COS**；COS 方案保留为以后可选能力。客户端已按纯文本读取自定义清单、移除 UTF-8 BOM 后解析 JSON；生成脚本输出 UTF-8 无 BOM。COS 尚未开通、没有真实桶域名、没有上传 APK/清单，也没有线上下载或线上通道验收。代码具备不等于国内更新通道已上线。

## 推荐方案：腾讯云 COS（需按实际账单计费）

不要按“每月免费 50GB 存储、10GB 下行流量、100 万次读请求”估算成本。腾讯云当前免费额度说明：个人新用户的 50GB 标准存储包有效期为开通后 6 个月（180 天），只抵扣标准存储容量，不抵扣请求次数和外网下行流量；官方示例中 10GB 外网下载按示例单价产生 5 元流量费。实际单价、地域、存储类型和优惠以控制台账单及[官方免费额度说明](https://cloud.tencent.com/document/api/436/6240)为准。上传前先确认桶的访问权限、流量计费和预算告警，避免将公开下载误认为免费。

### 一次性配置

1. 注册腾讯云并完成实名认证（微信扫码即可）。
2. 开通对象存储 COS，新建存储桶：名称如 `chaoxing-journal-updates`，**公有读私有写**，地域选就近（上海/广州）。
3. 记录桶的访问域名：`https://<桶名>.cos.<地域>.myqcloud.com`。

### 每次发布步骤

1. 构建与既有发布包身份一致的 APK。**不要把普通 `--debug` 构建视为稳定发布签名**：Debug 默认使用构建机的 debug keystore，不保证与用户现有体验包证书相同。当前 debug 和 release variant 均使用 `com.example.studyassistant.journal`；签名 Release 需要 `android/key.properties` 和维护者持有的既有体验私钥，不能以普通 Debug 包代替。后续若变更发布身份，仍须单独验证迁移与覆盖升级。COS 首次上线前，必须核对 applicationId、签名密钥保管与覆盖升级路径，并验证包名/证书/versionCode；没有同一发布身份时不得上传为可升级包。以下命令仅演示当前 debug flavor 的 manifest 参数注入，不是可直接发布的签名方案：

   ```powershell
   D:/campus-tools/flutter/bin/flutter.bat build apk --debug `
     --dart-define=UPDATE_MANIFEST_URL=https://<桶名>.cos.<地域>.myqcloud.com/update.json
   ```

   上述命令仅供开发阶段验证清单参数注入，不得把生成的普通 Debug APK 上传到 COS 作为用户升级包。实际发布必须先使用已确定的稳定 applicationId 和维护者持有的固定私钥完成 Release 签名，并通过同签名覆盖升级验证；正式身份方案未定前，停止在上传 APK 这一步。

2. 把 APK 传到桶内，例如 `updates/chaoxing-journal-1.6.3.apk`（控制台上传或 coscmd）。
3. 生成清单 JSON：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/update-manifest.ps1 `
     -ApkPath <apk路径> -VersionName 1.6.3 -VersionCode 48 `
     -ApkUrl https://<桶名>.cos.<地域>.myqcloud.com/updates/chaoxing-journal-1.6.3.apk `
     -OutPath update.json -Notes "发布说明"
   ```

4. 把 `update.json` 传到桶根目录（覆盖旧清单）。
5. 照常发布 GitHub Release（海外与备用渠道；GitHub 上的资产命名规则不变）。

### 注意事项

- **只有带 `--dart-define` 打出来的包才走清单通道**。1.6.2 及更早版本仍走 GitHub 通道；首次切换从 1.6.3 开始。客户端显式使用 `ResponseType.plain`，可解析 UTF-8 BOM 文本，不依赖 Dio 自动识别 JSON Content-Type；脚本输出 UTF-8 无 BOM。上传时仍应设置 `Content-Type: application/json`，首次真实下载前需用实际 COS URL 验证响应头、响应体和 APK 完整性。
- 清单里的 `versionCode` / `versionName` 必须与 APK 实际值一致，否则安装前身份核对会报"安装包身份与发布版本不符"。`scripts/update-manifest.ps1` 会从 APK 文件自动算 `size` 和 `sha256`，版本号不要手滑。
- APK 地址换镜像/换桶时，只需改桶里的 `update.json`，已发布的 App 无需重新打包。
- 不存在可据此保证“每月 70 次免费”的统一额度；请求与外网流量可能从首次下载开始计费。以腾讯云控制台账单为准。
- 模拟器验收：在确认同包名/同签名的隔离旧版本包上测试冷启动检查、清单下载、响应头/响应体、Range/完整长度、SHA-256 与覆盖安装；不得用不同签名 Debug 包或 release 默认不同 applicationId 的包替代正式升级验收。下载速度受网络与区域影响，不承诺“满速”。
