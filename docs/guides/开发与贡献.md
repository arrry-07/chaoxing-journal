Android 业务入口是 [`study_assistant-1.1.0/local_app`](../../study_assistant-1.1.0/local_app)。当前正式基线见 [PROJECT_STATE.md](../ai-workflow/PROJECT_STATE.md)，工作树版本见应用的 [pubspec.yaml](../../study_assistant-1.1.0/local_app/pubspec.yaml)。启动图标沿用 1.6.72 及以前的猫头像；未经维护者明确选稿，不替换原生 PNG 或新增候选资源。修改前阅读根目录 [AGENTS.md](../../AGENTS.md) 和相关实现、调用方及测试，保留已有修改。

## 环境与验证

使用 Flutter **3.44.9**（随附 Dart **3.12.2**）、JDK **17** 和 Android SDK **36**，与当前 [CI](../../.github/workflows/flutter-checks.yml) 保持一致。Android 构建配置还指定 NDK `28.2.13676358`。先用 `flutter --version`、`java -version`、`flutter doctor -v` 检查本机环境，再按需安装 Android 工具和接受 SDK 许可。

从仓库根目录执行：

```sh
cd study_assistant-1.1.0/local_app
flutter pub get --enforce-lockfile
dart analyze lib test # 含中文路径时勿在本地直接跑 flutter analyze --no-pub
flutter test --no-pub
flutter build apk --debug --no-pub --target-platform android-arm64,android-x64
```

这些检查与 CI 同源，依赖版本由已提交的 `pubspec.lock` 固定。不要为解决环境问题随意删除锁文件。构建结果通常为 `build/app/outputs/flutter-apk/app-debug.apk`；需要实际界面验证时再用 `flutter devices` 和 `flutter run` 选择设备。单元及组件测试通过不等于学习通真实账号、通知投递和所有机型已验证。

Flutter、JDK、SDK 可安装在适合自己的位置，文档或历史记录里的维护者本机路径不是前置要求。`android/local.properties` 中的 `sdk.dir`、`flutter.sdk` 应由本机生成；工具链路径、IDE 缓存和个人环境配置不提交到 Git。

参考 CLI 的 Python 3.13.14 在本机可运行，但固定参考版本的依赖和测试尚未在 2026-11-17 复核；不要仅凭命令位于 WindowsApps 路径就判定 Python 不可用，也不要据此声称参考 CLI 已通过。

Windows 上若工程通过 `subst` 或临时构建目录放在与 Pub Cache 不同的盘符，Kotlin 增量编译可能出现 `this and base files have different roots`。工程已在 `android/gradle.properties` 中设置 `kotlin.incremental=false` 规避该跨盘符异常，并保留 Gradle 任务级 `UP-TO-DATE` 缓存；日常无需删除整个 Pub Cache。若本机 `local.properties` 指向不可用 SDK，优先在当前 PowerShell 进程设置 `ANDROID_HOME`、`ANDROID_SDK_ROOT` 和 `JAVA_HOME`，不要把机器路径提交到仓库。

Android Maven 依赖在 `CI=true` 时于官方仓库前接入 `GoogleMavenCentralMirror`（并排除 `com.android.*` 与 `androidx.*`，确保 Android/AndroidX 仅走官方 `google()`），避免镜像故障阻断远端构建；本地保留现有镜像优先顺序。两种配置均不改变依赖版本。

## 从哪里读代码

| 位置 | 职责 |
| --- | --- |
| `lib/main.dart`、`lib/src/app/` | 启动、导航、主题和版本 |
| `lib/src/features/` | 首页、日历、统计、个人页等界面 |
| `lib/src/services/assignment_store.dart` | 同步状态、课程关注、提醒和本机记录协调 |
| `lib/src/local/` | 学习通请求、解析与本机持久化 |
| `lib/src/services/secure_session_store.dart` | 账号与密码的安全存储 |
| `android/app/src/main/` | Android 通道、访问验证、通知及小组件 |
| `test/` | Flutter 自动化测试 |

应用启动图标当前使用 Android 原生 `mipmap-*` PNG；1.7.4 已恢复 1.6.72 及以前使用的猫头像。未经维护者明确选稿，不替换这些 PNG，也不新增自适应、单色或候选图标资源。桌面启动图标与课程列表书本图标用途不同，不要互相复用。

Android 8.0（API 26）及以上的通知必须先注册通知渠道。`LocalNotificationService` 在初始化阶段逐个检查并补建核心渠道（`assignment_deadlines`、`assignment_updates`、`daily_summary`、`personal_schedule`），`1.8.26` 起同时维护版本化有声截止渠道 `assignment_deadlines_v2`（新装默认 `v2`，升级保守沿用 `v1` 并提供显式切换）与低重要性 `assignment_silent`（未知时间新作业）；已存在的渠道不重新注册，以免覆盖用户自定义配置。个人日程与每日摘要继续使用既有补偿式 `staging/committed` 通知事务；学习通截止事件使用应用私有 SQLite（`1.8.26` 正式基线已升至 `ReminderDatabase` `v8`）+ AlarmManager，并按 `DeadlineQuietHoursPolicy`（`[23:30, 07:30)` 默认静音顺延与按账号可选 `≤1h` 紧急穿透）在原生投递前二次校验账号代次、完成/隐藏/关注/归档状态、来源与有效截止及隐私设置。旧插件 `a:` 作业提醒先完成类别限定的取消迁移，新旧投递器不得同时生效；迁移不确定时暂停该账号作业自动投递并在体检中提示。原有摘要和个人提醒事务不能被简化为全局取消后重建。

学习通作业后台检查使用一个唯一的一次性 WorkManager 链。Worker 使用独立、不 `runApp()` 的 `backgroundMain` Flutter 入口，复用安全存储、学习通客户端、本地仓库和提醒规划；停止时取消网络并拒绝迟到提交。前台、Worker 和原生桥接共享进程内同步租约、写租约、账号会话代次与提醒 mutation version。SharedPreferences 与 SQLite 不是同一数据库事务，因此先标记快照待更新，完成仓库写入后以读取时的 mutation version 提交提醒快照；版本不符必须拒绝并重做计划。时间规则、监听过滤、稳定通知 ID 与数据库策略的 JVM 测试位于 `android/app/src/test/`，Flutter 规则与集成测试位于 `test/daytime_check_policy_test.dart`、`assignment_reminder_planner_test.dart` 和 `assignment_store_background_reminder_test.dart`。

Windows 原始工程路径若含中文字符，AGP 可能在配置阶段拒绝构建；`android.overridePathCheck=true` 只能绕过该前置检查，CMake 仍可能因生成路径 JSON 转义失败。可将当前工作树的 Flutter 工程复制到 ASCII 临时构建目录，在副本中配置 SDK/JDK 并构建；先确认副本包含当前全部源码、测试、资源与 Android 原生文件。工程已在 `android/gradle.properties` 中设置 `kotlin.incremental=false`，以避免 Pub Cache 在 C 盘、工程在 D 盘时触发 `this and base files have different roots` 跨盘符增量编译异常。在构建前按 Git 跟踪范围核对副本，确保来自当前工作树。Flutter 目标平台使用 `--target-platform android-arm64,android-x64`；`android/app/build.gradle` 排除全部 `lib/armeabi-v7a/**`，构建后运行 `python tool/check_apk_abis.py build/app/outputs/flutter-apk/app-debug.apk --abi arm64-v8a --abi x86_64`，确认没有引擎外 ABI 且两个目标 ABI 都包含 `libflutter.so`。Release 构建时 `IconTreeShaker` 输出的 `packages/cupertino_icons/CupertinoIcons` 提示来自第三方 `go_router` 内部未使用的 `CupertinoErrorScreen` 常量扫描，业务代码无 `CupertinoIcons` 引用且不影响 `MaterialIcons` 字体裁剪（98.9% 缩减），无需为此引入 `cupertino_icons` 依赖。不要删除整个 Pub Cache，也不要把临时构建配置写回共享工作树。

表中路径均相对于 Flutter 应用目录。修改同步逻辑时注意：读取失败不能被当作零作业；截止时间未知不能推断成无截止；本机隐藏不能写成学习通已提交；课程身份需区分课程与班级。

## 首页课业排序长期约束

- 普通首页只展示未完成目录。已提交作业、已结束／已取消／可信结束已过的考试与历史课堂练习通过本地记录和统计查看。同搜索、课程及期限条件下，类型「全部」等于「作业」与「考试」按展示记录身份合并；「作业」含正式作业和课程任务。`filtersActive` 只控制筛选提示及清除入口，日历待核对、每日计划推荐沿用 `currentDisplay`。
- 普通首页先从当前筛选结果提取按账号保存的置顶项。常规课业依次排列为未确认逾期且有可用展示时间、未确认逾期且无可用展示时间、确认逾期。中间层按课程、名称、课程身份、记录 ID 稳定排序。作业和课堂活动用截止时间，考试用开考时间。提交、结束或未知状态本身不改变时间层级。
- 常规有时间层按所选方向比较完整时间。逾期可手动置顶。未置顶的确认逾期始终位于普通时间轴底部，层内「近到远」按最近截止在前，「远到近」按最早截止在前。普通首页有开始时间或原文、无截止的已确认待交作业和任务纳入「未逾期」，「近到远」时在七天内有时间记录之后、七天以外之前，「远到近」时在有时间记录之后。完全无时间、历史截止待核实、已过时考试通知保留原有层级；恢复范围和本地记录继续用常规排序。
- 同课程、班级和考试身份中唯一且可投影的缺年开考时间可用于排序。冲突、只有结束时间或无法投影时继续居中稳定排序。日期标题保留原月日与年份待确认提示。期限筛选、日历、提醒和持久化各自使用可信时间。
- 无日期卡保留左栏占位，确认无截止显示「—」，其余显示「待定」。连续段以「无日期与待确认」分组，保持原顺序，恢复范围页省略该标题。跨天考试标题显示起止，结束段仅跨年加年；无开考时间但有可用范围或结束时间时在卡内显示范围。显示范围不写回时间信任、日历、提醒或备份。
- 调整排序时保留或扩充 `FB-005` 命名回归，验证首页、筛选目录和到期分组。已提交记录保留普通课业排版。

## MuMu 自测包

- 仅准备安装自测包时才在 `dev` 同步修改 `pubspec.yaml` 与 `AppVersion`，按[版本号与迭代规则](../ai-workflow/VALIDATION.md#版本号与迭代分级规则)在当前版本上递增第三位补丁号 `Z+1` 与构建号 `+build`（纯三段无前导零 `X.Y.Z+build`，如 `1.8.27+121`、`1.8.28+122`，不使用 `-dev.N` 后缀）；构建号高于已用值及设备当前安装值，且不提前写入正式版 `CHANGELOG.md`、`README.md` 与安装指南。
- 用 `flutter build apk --release --no-pub --target-platform <MuMu 对应平台>` 和本机缓存构建对应单架构。`--split-per-abi` 会给实际 versionCode 加偏移，影响正式包覆盖。
- 核对包名、架构、实际版本码与原签名后，用 `adb -s 127.0.0.1:16448 install -r <APK>` 覆盖「学习通」实例，保留登录态和课业。登录、Cookie、安全验证续接、数据迁移或 Kotlin 改动按影响安排同签名覆盖。离线预览时断开外网，真实账号刷新单独安排，破坏性测试使用隔离实例。
- 记录实际安装版本、数据保留和本阶段关键交互。阶段自测通过后按[迭代流程](../ai-workflow/VALIDATION.md#先确定本次终点)给出下一阶段规划提示词。正式发布的版本冻结和授权见[版本规则](../ai-workflow/VALIDATION.md#版本号与迭代分级规则)。

## 安装身份与发布

当前 debug 与 release 构建均使用 `com.example.studyassistant.journal`（基础 applicationId 加 `.journal` 后缀），沿用现有体验发布身份。正式 APK 是非 debuggable 的 Release 构建，但证书沿用 Android Debug 体验证书（证书主题仍为 Android Debug），不是生产或应用商店签名；升级兼容依赖同一证书。调试密钥随构建环境而异，自己构建的 APK 不保证能覆盖体验包；相同包名也不能替代签名核对。历史基础包名 `com.example.studyassistant` 不代表当前 Release 的最终安装身份。

正式构建要求本机的 `android/key.properties` 和私有签名密钥；仓库不提供默认正式签名，缺少配置会阻止 release 构建。不要把密钥、口令、`key.properties`、账号、Cookie、APK 或设备数据提交到仓库。若维护发布渠道，必须先决定稳定的包名、密钥保管与升级迁移方案，再构建分发。

默认官方更新源会并行检查 Gitee `update-manual.json` 与 `arrry-07/chaoxing-journal` 的 GitHub 正式 Release 列表，只使用正式发布。两源都有候选时按显示版本选择，同版本优先 GitHub 元数据；大小和 SHA-256 一致时下载优先 Gitee 地址并保留 GitHub 备用，冲突时只保留 GitHub。启动检查与手动检查都读取正式发布，启动可提示同主/次版本补丁，但保留忽略版本和手动检查；按现行发版规则，正式版一律升第二位 `Y`（上限 `99`，满 `99` 进第一位 `X`），因此每次正式发布均同步推进 `update-stable.json` 与 `update-manual.json`。

当前分发状态见 [PROJECT_STATE.md](../ai-workflow/PROJECT_STATE.md)。正式 APK 与校验文件的约定见[更新渠道与国内分发](更新渠道与国内分发.md)。

自定义更新源优先使用 `UPDATE_STABLE_MANIFEST_URL` 与 `UPDATE_MANUAL_MANIFEST_URL` 两个 HTTPS 清单：启动入口只接受 major/minor 提升，手动入口可发现最新补丁。旧 `UPDATE_MANIFEST_URL` 继续兼容为单清单。清单必须包含 `versionCode`、`versionName`、`applicationId`、`apkUrl`、`sha256`、`size`，可含 `notes` 和同摘要备用地址。未显式配置时使用默认 Gitee + GitHub 双源；显式配置自定义清单后，清单失败不会降级到另一来源。主分支提交、草稿和预发布不会被当作正式升级包。

更新任务由应用级 `AppUpdateController` 持有，弹窗与底部进度条只观察任务。新增入口需复用该控制器，避免关闭页面取消下载或创建重复任务；后台完成不自动打开安装器。原生安装前校验包名、签名、递增版本码、SDK 与 ABI，禁止为兼容测试绕过这些检查。系统终止进程后不保证继续下载。
