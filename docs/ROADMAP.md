## 工程化建设后期规划（待排期）

> **执行门禁声明**：本节全部 5 项均为后期工程化规划。未来项目推进到对应触发节点、准备开始落地其中任意一项前，**必须先主动询问维护者意见并获得明确同意后再执行**，严禁未征求确认即修改业务代码、脚本、Git Hook 或 CI 配置。

### 波次 A：安全护栏与 AI 协作门禁

- **状态**：`待排期`
- **核心收益**：将目前依赖人工 / AI 复核的敏感文件防误入与交付前验证固化为底层硬拦截和统一一键入口，降低跨模型或新会话的规范漂移风险。
- **建议触发时机**：轻巧优先，建议在下一轮大改动前询问落地。
- **执行门禁**：落地前须先征求用户确认。

1. **推送与安全门禁工程化（底层硬拦截）**
   - **目标**：将目前依赖人工 / AI 复核的推送门禁固化为本地 Git Hooks（`pre-commit` / `pre-push`）与仓库级安全扫描脚本。
   - **范围**：自动拦截 `.apk`、签名密钥、Cookie / 账号响应、敏感目录（如 `docs/feedback/`、`scripts/demo-video/` 等）及大体积二进制文件误入暂存区或推送。
2. **AI 协作工程化（统一本地一键验证门禁）**
   - **目标**：沉淀统一入口验证脚本（串联格式检查、静态分析、`check_release_metadata.py`、全量测试、敏感文件扫描与构建噪音检查），并在 `AGENTS.md` 中约定为代码交付前必跑门禁，同时梳理完善本地 Skills 触发路由表，确保换模型或新会话都能稳定遵循项目规范。

### 波次 B：UI 设计系统与视觉防回归

- **状态**：`待排期`
- **核心收益**：以单一真相源 Design Tokens 消除页面硬编码色值与风格漂移，通过静态守卫与 Golden 截图回归守住核心页面浅 / 深双色视觉基线。
- **建议触发时机**：建议随《全应用 UI/UX 升级》同步落地。
- **执行门禁**：落地前须先征求用户确认。

3. **UI 设计系统与视觉防回归工程化**
   - **目标**：建立单一真相源的 Design Tokens（浅色暖纸 + 深夜台灯炭灰双色板、圆角、2px 无底框线性图标、统一物理动效参数），杜绝页面硬编码色值与突兀亮蓝大按钮。
   - **守卫**：增加 UI 静态规范检查 / 单测（禁止新代码引入原生 `DropdownButtonFormField`），并为核心页面（首页、日历、统计、我的，浅色 + 深色）补齐 Flutter Golden 截图回归测试。

### 波次 C：发版联动与官网素材自动化

- **状态**：`待排期`
- **核心收益**：打通主仓发版到官网四方 SHA-256 核验上线的自动闭环，并用零隐私合成演示数据与自动截图产线替代手动打码与易过时截图。
- **建议触发时机**：建议在 UI 大升级完成、准备发大版本时询问落地。
- **执行门禁**：落地前须先征求用户确认。

4. **一键发版与双仓联动工程化**
   - **目标**：补齐版本号冻结 / Changelog 生成 / 门禁联跑辅助脚本，并完善主仓正式 Release 发布后通过 `repository_dispatch` 自动唤醒官网仓库 `arrry-07/chaoxing-journal-site`（`sync-release.yml`）在 1 分钟内完成四方 SHA-256 核验并部署上线。
5. **合成样例数据与官网截图自动产线**
   - **目标**：在 App 内维护一套固定的零隐私合成演示数据（Demo Fixture），配合集成测试脚本一键自动截取浅色 / 深色高清真机图，直接用于同步更新官网展示素材，告别手动打码与截图过时。
